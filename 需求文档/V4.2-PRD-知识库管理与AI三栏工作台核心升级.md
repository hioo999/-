# V4.2 PRD：知识库管理与 AI 三栏工作台核心升级

> 基于用户新增核心需求整理  
> 版本定位：在 V4.1 Agent 本地数据主权闭环上，升级为“私人/团队/案件知识库 + 文件中台 + 组织权限 + AI 工作台”  
> 文档类型：产品需求文档 PRD  
> 版本：V4.2  
> 日期：2026-05-29  
> 产品经理视角：小P

## 1. 文档说明

### 1.1 文档目的

本文档用于承接新的核心产品方向：系统不再只是“案件资料 AI 问答助手”，而要升级为律师和律所可长期使用的本地知识库工作平台。

V4.2 的核心目标是把以下能力产品化：

```text
私人知识库
+ 团队知识库
+ 案件知识库
+ 多方式文件管理
+ 企业组织架构同步
+ 细粒度权限
+ 中间文件预览
+ 右侧 AI 对话
+ 提示词和 skills 管理
```

### 1.2 用户原始需求摘要

用户希望的管理逻辑如下：

| 参考方向 | 用户诉求 | 产品抽象 |
|---|---|---|
| 类似 IMA | 分私人知识库、团队知识库，每个知识库可自由管理文件，多种上传方式 | 知识库空间体系 + 文件中台 |
| 类似 IMA 组织接入 | 团队知识库可由管理员添加成员，也可从钉钉、企微、飞书拉取企业组织架构 | 本地组织与外部组织同步 |
| 自由设定权限 | 团队知识库、目录、文件、操作均可控 | 多层级 RBAC/ACL 权限 |
| 类似乐享 | 后台应有的功能要有 | 律所知识管理后台，但围绕律师场景裁剪 |
| 类似 Cursor | 中间预览文件，右侧 AI 对话框 | 三栏 AI 工作台 |
| 新增核心功能 | 提示词、skills 管理 | AI 能力配置后台 |

说明：当前模型无法直接读取用户提到的图片，因此本文档以用户文字描述和问答选择为准。

### 1.3 与 V4/V4.1 的关系

V4.1 的重点是验证：

```text
Agent 本地部署 -> 本地资料入库 -> 本地解析/向量化 -> 案件问答带来源 -> 平台不可见律师业务数据
```

V4.2 的重点是扩展：

```text
单案件资料问答
-> 私人/团队/案件多知识库管理
-> 类网盘文件管理和权限协作
-> 组织架构同步
-> 文件预览 + AI 上下文问答 + 引用写作
-> 律所知识后台
```

V4.2 不改变 V4/V4.1 的安全红线：平台仍不可见律师业务数据，所有文件、正文、向量、问答、提示词执行结果、审计明细默认在律师侧 Agent 本地保存和处理。

## 2. 产品定位

### 2.1 一句话定义

```text
一个部署在律师本地、支持私人/团队/案件知识库管理、组织权限管控、文件预览和可溯源 AI 对话的律师知识工作台。
```

### 2.2 产品核心价值

| 价值 | 说明 |
|---|---|
| 资料集中 | 律师可把个人资料、团队资料、案件资料统一纳入知识库管理 |
| 权限可控 | 律所管理员可按组织、成员、角色、知识库、文件夹、文件、操作进行授权 |
| 不破坏原资料 | 支持上传副本，也支持扫描本地目录，尽量不改变律师原有文件整理习惯 |
| AI 可用 | 预览文件时可直接让 AI 基于当前文件、选中文本、目录、知识库或案件回答 |
| 来源可查 | AI 回答必须尽可能给出文件名、页码、段落、引用原文和置信提示 |
| 后台可管 | 律所可管理知识库、组织、成员、权限、提示词、skills、审计和模型配置 |
| 数据主权 | 平台控制平面仍不能读取律师业务数据 |

### 2.3 产品不是什么

V4.2 不是普通云网盘。

V4.2 不是平台托管律师数据的 SaaS 知识库。

V4.2 不是开放给公众的法律咨询机器人。

V4.2 不是完整复刻乐享的培训、积分、学习平台。

V4.2 不是只做聊天窗口的 AI 助手。

## 3. 目标用户与角色

### 3.1 目标用户

| 用户 | 优先级 | 核心诉求 |
|---|---|---|
| 单个律师 | P0 | 管理个人资料、案件资料，快速检索和问答 |
| 主办律师 | P0 | 建案件知识库、授权助理/协办律师、核验 AI 引用 |
| 律师助理 | P0 | 上传、整理、标注、预览文件，辅助生成证据和摘要 |
| 协办律师 | P0 | 查看授权案件和团队知识，参与问答和写作 |
| 律所管理员 | P0 | 管团队知识库、组织架构、成员、角色、权限、审计 |
| Agent 管理员 | P0 | 管本地数据源、模型、索引任务、组织同步连接器 |
| 合伙人/主任 | P1 | 掌握团队知识资产，控制共享范围和合规风险 |
| 平台管理员 | P0 | 管授权、Agent 状态、脱敏健康，不接触业务数据 |

### 3.2 角色定义

| 角色 | 权限定位 |
|---|---|
| 平台管理员 | 只能管理平台账号、组织授权、Agent 在线状态、脱敏健康数据 |
| Agent 管理员 | 管本地 Agent、数据源、索引、模型、组织同步、系统审计 |
| 律所管理员 | 管律所成员、部门、团队知识库、角色、权限、后台配置 |
| 知识库管理员 | 管指定知识库的成员、目录、文件、标签、权限和 AI 设置 |
| 主办律师 | 管自己负责的案件知识库，决定案件资料共享范围 |
| 编辑者 | 可上传、编辑、标注、移动文件，具体以授权为准 |
| 查看者 | 可查看、预览、检索，是否可 AI 问答由操作权限控制 |
| 只读成员 | 仅查看，不可上传、删除、授权、导出 |
| 禁止访问者 | 对指定知识库、目录或文件无可见权限 |

## 4. 知识库空间设计

### 4.1 知识库类型

V4.2 第一版支持三类知识库：

| 类型 | 归属 | 典型内容 | 默认可见范围 | 优先级 |
|---|---|---|---|---|
| 私人知识库 | 个人用户 | 个人笔记、合同模板、法规资料、办案经验 | 仅本人 | P0 |
| 团队知识库 | 律所/部门/团队 | 团队模板、案例资料、研究资料、共享制度 | 授权团队成员 | P0 |
| 案件知识库 | 案件空间 | 案件文件、证据、笔录、判决、往来材料 | 案件授权成员 | P0 |

### 4.2 知识库关系

| 关系 | 说明 |
|---|---|
| 私人知识库独立 | 默认不进入团队共享，用户可主动分享文件或目录 |
| 团队知识库可多层 | 可按律所、部门、项目组创建多个团队知识库 |
| 案件知识库关联案件 | 创建案件时可自动创建同名案件知识库 |
| 文件可引用不复制 | 同一文件可被多个知识库引用，避免重复存储 |
| 文件可复制入库 | 对外部来源文件也可选择复制到 Agent 本地存储 |
| 权限取最小可用 | 用户访问文件时必须同时满足知识库权限和文件权限 |

### 4.3 知识库基础字段

| 字段 | 说明 |
|---|---|
| 知识库名称 | 必填，支持重命名 |
| 知识库类型 | private/team/case |
| 归属主体 | 用户、部门、团队、案件 |
| 管理员 | 至少 1 个 |
| 描述 | 可选 |
| 可见范围 | 私密、指定成员、指定部门、全律所 |
| 默认文件权限 | 新文件继承的权限策略 |
| AI 使用范围 | 是否允许被 AI 检索和问答 |
| 审计策略 | 是否记录预览、下载、问答、导出 |
| 状态 | active/archived/disabled |

## 6. 核心页面形态

### 6.1 三栏 AI 工作台

V4.2 的核心工作台采用三栏结构：

| 区域 | 功能 | 说明 |
|---|---|---|
| 左侧 | 知识库/目录/文件树 | 可切换私人、团队、案件知识库 |
| 中间 | 文件预览区 | 预览 PDF、Word、图片、文本、表格等文件 |
| 右侧 | AI 对话区 | 类 Cursor 对话框，支持基于上下文问答、改写、总结、生成 |

### 6.2 左侧知识库与文件树

左侧需要支持：

| 功能 | 优先级 | 验收标准 |
|---|---|---|
| 切换知识库类型 | P0 | 可在私人、团队、案件之间切换 |
| 目录树 | P0 | 支持多级目录展开、收起、搜索 |
| 文件状态 | P0 | 展示未解析、解析中、已索引、失败状态 |
| 权限提示 | P0 | 无权限文件不可见或置灰，并说明原因 |
| 快捷操作 | P0 | 上传、新建目录、重命名、移动、删除、授权入口 |

### 6.3 中间文件预览区

中间区域需要支持：

| 文件类型 | 预览要求 | 优先级 |
|---|---|---|
| PDF | 分页预览、页码定位、文本选择 | P0 |
| Word | 转文本/HTML 预览，保留基础段落结构 | P0 |
| 图片 | 图片预览、OCR 文本侧栏或弹层 | P0 |
| TXT/MD | 原文预览、文本选择 | P0 |
| CSV/Excel | 表格预览、列宽、分页 | P1 |
| 音视频 | 元信息和转写结果预览 | P2 |

中间预览区必须支持选中文本后调用 AI：

| 操作 | 说明 | 优先级 |
|---|---|---|
| 解释选中文本 | AI 基于选中文本解释含义 | P0 |
| 总结当前页 | AI 总结当前页或当前段落 | P0 |
| 提取证据点 | AI 提取与案件争议相关的证据点 | P0 |
| 生成引用 | AI 生成带文件名、页码、段落的引用说明 | P0 |
| 加入上下文 | 将选中文本加入右侧对话上下文 | P0 |

### 6.4 右侧 AI 对话区

右侧 AI 对话区需要支持：

| 功能 | 说明 | 优先级 |
|---|---|---|
| 上下文范围选择 | 当前文件、选中文本、当前目录、当前知识库、当前案件、跨库 | P0 |
| 对话输入 | 支持自然语言提问和快捷指令 | P0 |
| 引用展示 | 展示来源文件、页码、段落、原文片段 | P0 |
| 引用跳转 | 点击引用后中间预览区跳转到对应位置 | P0 |
| 写作辅助 | 摘要、争议焦点、证据目录、文书片段 | P0 |
| 无依据提示 | 检索不到依据时必须提示“未在授权资料中找到依据” | P0 |
| 历史记录 | 保存本地对话历史，可按知识库/案件检索 | P1 |
| 一键插入 | 将 AI 结果插入笔记、证据目录、文书草稿 | P1 |

### 7.3 上传与导入方式

| 来源 | 方式 | 优先级 | 安全要求 |
|---|---|---|---|
| 本地文件 | 浏览器上传 | P0 | 文件留存在 Agent 本地 |
| 本地文件夹 | 文件夹上传 | P0 | 保留目录结构 |
| 本地目录 | Agent 扫描 | P0 | 必须先授权目录，禁止敏感路径 |
| URL | 后端拉取 | P1 | 限制内网/公网策略、防 SSRF |
| 钉钉 | 组织与附件连接器 | P0/P1 | OAuth/应用凭证本地加密 |
| 企业微信 | 组织与附件连接器 | P0/P1 | OAuth/应用凭证本地加密 |
| 飞书 | 组织与附件连接器 | P0/P1 | OAuth/应用凭证本地加密 |
| 数据库 | 只读连接器 | P1 | 只读账号、字段白名单、数据不出本地 |

第一版范围建议：组织同步 P0 至少完成一个外部连接器落地，钉钉/企微/飞书其余连接器按相同适配层扩展。文件附件导入可以作为 P1，但接口设计需在 P0 预留。

### 7.4 组织架构与成员管理

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| ORG-001 | 支持手动创建成员 | P0 | 管理员可创建、禁用、重置密码 |
| ORG-002 | 支持部门树 | P0 | 可创建多级部门并分配成员 |

### 7.5 权限管理

V4.2 权限需要覆盖知识库级、文件级、操作级。

| 权限层级 | 说明 | 优先级 |
|---|---|---|
| 知识库级 | 控制用户是否可访问某个知识库 | P0 |
| 目录级 | 控制用户是否可访问某个目录及子目录 | P0 |
| 文件级 | 控制用户是否可访问单个文件 | P0 |
| 操作级 | 控制查看、下载、上传、删除、授权、AI 问答、导出等动作 | P0 |

操作权限定义：

| 权限 | 说明 | 优先级 |
|---|---|---|
| view | 查看列表和基础信息 | P0 |
| preview | 打开文件预览 | P0 |
| upload | 上传或导入文件 | P0 |
| edit | 重命名、移动、打标签、编辑元数据 | P0 |
| delete | 删除到回收站 | P0 |
| purge | 彻底删除 | P1 |
| download | 下载文件 | P0 |
| ai_query | 基于文件或知识库 AI 问答 | P0 |
| export | 导出证据目录、问答结果、文书草稿 | P1 |
| share | 分享文件或目录给其他成员 | P1 |
| grant | 管理成员和权限 | P0 |
| audit_view | 查看审计日志 | P0 |

权限计算规则：

| 规则 | 说明 |
|---|---|
| 默认继承 | 文件默认继承所在目录和知识库权限 |
| 显式拒绝优先 | 如果存在明确禁止访问，则优先禁止 |
| 最小权限原则 | 同一用户多个角色叠加时，敏感操作需显式授权 |
| 管理员兜底 | 知识库管理员可管理本知识库，但不能越权访问其他知识库 |
| 案件隔离 | 未被案件授权的成员不能通过团队知识库侧绕过案件文件权限 |
| AI 同权 | AI 可检索范围不得超过当前用户可访问范围 |

## 9. 关键业务流程

### 9.1 私人知识库流程

```text
用户登录
-> 创建私人知识库
-> 上传文件/文件夹或扫描本地目录
-> 系统解析/OCR/向量化
-> 用户预览文件
-> 右侧 AI 基于当前文件或私人知识库问答
-> AI 输出引用
-> 用户保存为笔记或提示词模板
```

### 9.2 团队知识库流程

```text
律所管理员创建团队知识库
-> 手动添加成员或同步外部组织架构
-> 设置知识库管理员和成员角色
-> 上传团队文件或导入共享附件
-> 设置目录/文件权限
-> 团队成员按权限检索、预览、问答
-> 审计日志记录关键操作
```

### 9.3 案件知识库流程

```text
主办律师创建案件
-> 系统自动创建案件知识库
-> 主办律师授权协办律师和助理
-> 上传或关联案件文件
-> 文件解析、OCR、向量化
-> 三栏工作台预览材料
-> AI 基于案件资料生成摘要、争议焦点、证据目录
-> 律师核验引用并确认结果
```

### 9.4 组织同步流程

```text
Agent 管理员配置钉钉/企微/飞书应用凭证
-> 本地 Agent 拉取部门和成员
-> 系统生成同步预览
-> 管理员确认新增、更新、禁用策略
-> 同步到本地组织架构
-> 团队知识库可按部门和成员授权
-> 同步日志保存到本地审计
```

### 9.5 AI 引用核验流程

```text
用户提出问题
-> 系统根据用户选择确定上下文范围
-> 权限过滤可检索文件
-> 检索相关片段
-> 模型生成回答
-> 回答附带引用
-> 用户点击引用跳转预览区
-> 用户标记采纳、修改或废弃
```

## 13. 验收标准

### 13.1 功能验收

| 场景 | 验收标准 |
|---|---|
| 私人知识库 | 用户可创建私人知识库并上传文件，其他用户默认不可见 |
| 团队知识库 | 管理员可创建团队知识库并授权成员访问 |
| 案件知识库 | 创建案件后可自动创建案件知识库并授权案件成员 |
| 文件管理 | 支持上传、预览、解析、标签、搜索、删除到回收站 |
| 权限控制 | 无权限成员看不到知识库、目录、文件和 AI 引用 |
| 组织同步 | 至少一种外部组织来源可同步部门和成员 |
| 三栏工作台 | 左侧切库，中间预览，右侧 AI 问答可正常联动 |
| 引用跳转 | AI 回答引用可跳转到中间预览区对应位置 |
| 提示词 | 管理员可创建提示词模板并在 AI 工作台使用 |
| Skills | 用户可调用授权 skill，调用过程有本地审计记录 |

### 13.2 安全验收

| 项目 | 验收标准 |
|---|---|
| 平台不可见 | 平台接口和日志不出现知识库名、文件名、正文、问答、提示词 |
| AI 不越权 | 用户无权限的文件不能进入检索结果和引用 |
| 外部凭证 | 钉钉/企微/飞书和模型 API Key 本地加密保存 |
| 审计日志 | 预览、下载、删除、授权、问答、导出均有本地日志 |
| 敏感目录 | Agent 拒绝扫描系统敏感路径 |

### 13.3 体验验收

| 项目 | 验收标准 |
|---|---|
| 文件预览 | 常见 PDF/Word/图片/文本可在中间区域打开 |
| AI 对话 | 右侧对话不遮挡文件预览，可持续追问 |
| 上下文选择 | 用户能明确知道 AI 当前基于什么范围回答 |
| 无依据提示 | 检索不到依据时提示明确，不给确定性假答案 |
| 权限反馈 | 无权限时展示清晰原因和申请入口 |

| 需求范围过大 | MVP 周期失控 | 坚持核心闭环优先，乐享类非核心运营功能后置 |
| 三方组织 API 差异大 | 组织同步延期 | 先抽象统一组织模型，首版落地一种连接器 |
| 文件权限过细 | 设计和测试复杂 | MVP 做知识库、目录、文件、操作四层基础模型 |
| AI 越权风险 | 严重安全问题 | 检索层必须做权限过滤，引用层二次校验 |
| 文件预览格式复杂 | 体验不稳定 | 首版优先 PDF/Word/图片/TXT，Excel P1 优化 |
| 律师不信 AI | 使用率低 | 强化引用跳转、原文核验、律师确认机制 |
| 平台不可见被破坏 | 产品定位失效 | 平台接口、日志、诊断包必须有自动化检查 |

### 14.2 关键产品决策

| 决策 | 结论 |
|---|---|
| 是否全量复刻乐享 | 不全量复刻，只借鉴后台框架，围绕律师知识库裁剪 |
| 是否第一版做三类知识库 | 是，私人、团队、案件均为 P0 |
| 是否第一版做组织同步 | 是，但建议先完成一种外部来源，其他按适配层扩展 |
| 是否第一版做细权限 | 是，至少做到知识库、目录/文件、操作级 |
| 是否第一版做三栏 AI | 是，这是核心体验 |
| 是否第一版做提示词和 skills | 是，做基础管理和内置 skills |
| 是否保持平台不可见 | 必须保持，不允许妥协 |

## 16. 小P结论

V4.2 的产品重心应从“单个案件 AI 问答”升级为“律师知识资产管理平台”。

第一优先级不是把乐享所有功能搬过来，而是跑通以下核心闭环：

```text
创建私人/团队/案件知识库
-> 上传和管理文件
-> 按组织和角色授权
-> 文件解析和预览
-> 右侧 AI 基于授权上下文问答
-> AI 给出可跳转引用
-> 律师确认和沉淀结果
```

这条闭环一旦跑通，系统就具备了从“工具”变成“律所知识基础设施”的基础。
