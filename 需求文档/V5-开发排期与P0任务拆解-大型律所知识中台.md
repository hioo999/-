# V5 开发排期与 P0 任务拆解：大型律所知识中台与风险可控 AI 工作台

> 基于 `V5-PRD-大型律所知识中台与风险可控AI工作台.md` 拆解  
> 角色视角：产品经理小P  
> 目标：把大型律所级知识治理、专业分类、审核发布、权限隔离和 AI 风控要求转化为可开发、可测试、可验收的版本排期  
> 日期：2026-05-30

---

## 1. 排期结论

V5 不继续优先堆叠新 AI 技能，而是先把知识中台底座补齐。研发顺序采用“知识治理先行、AI 受控接入、管理指标后置扩展”的路径。

| 阶段 | 周期 | 目标 | 交付重点 |
|---|---:|---|---|
| V5-M0 | 第 1 周 | V4.2 基线冻结 | 现有知识库、文件、ACL、RAG、企业管理测试继续通过 |
| V5-M1 | 第 1-2 周 | 知识治理元数据 | 知识类型、审核状态、维护人、有效期、保密等级、AI 使用规则 |
| V5-M2 | 第 2-3 周 | 审核发布流程 | 草稿、待审核、已发布、退回、废止、需更新、禁止 AI 使用状态流转 |
| V5-M3 | 第 3-4 周 | AI 法律回答风控 | 强制结构化回答、证据不足拒答、仅检索不可生成、高敏禁用 AI |
| V5-M4 | 第 4-5 周 | 大所权限隔离基础 | 客户、案件、部门、项目组维度标签和 ACL 组合校验 |
| V5-M5 | 第 5-6 周 | 管理看板 P0 | 知识数量、文件数量、成员数量、使用质量、过期风险、差评问答 |
| V5-M6 | 第 6 周 | 试点验收 | 部门级试点清单、权限越权测试、AI 风控验收、交付报告 |

## 3.1 2026-06-02 联调补强记录

本轮继续推进 `V5-P0-004 AI 使用范围控制`，重点补强“禁止 AI 使用”的底层红线。

| 项目 | 处理结果 |
|---|---|
| 发现问题 | API 路由已阻断 `disabled` / `ai_disabled` 知识库检索，但底层 `Store.search()` 只检查文件级策略，存在内部调用绕过知识库级禁用策略并返回旧文件命中的风险 |
| 修复动作 | 新增 `scope_allows_ai_usage()`，将知识库级 `ai_enabled`、`ai_usage_policy`、`review_status`、有效期和发布状态检查下沉到 `Store.search()` |
| 验收锁定 | 在 `test_knowledge_base_review_transitions_are_audited` 中增加断言：知识库执行 `disable_ai` 后，普通检索与生成检索均返回空结果，生成问答继续抛出拒绝 |
| 验证结果 | `test_m24_knowledge_base_data_plane.py` 共 18 个用例通过 |

该补强后，`disabled` / `ai_disabled` 不再只依赖 FastAPI 路由保护，底层 Store 内部调用也会遵守“禁止 AI 使用不检索、不生成、不引用”的 P0 红线。

## 3.2 2026-06-02 P0-05 联调记录

本轮继续推进 `V5-P0-005 引用与证据不足拒答`，重点补强历史问答中的证据不足可识别性。

| 项目 | 处理结果 |
|---|---|
| 发现问题 | 当前无依据回答会写入“证据不足”正文并保存 `has_citations = 0`，但历史消息接口没有显式返回 `insufficient_evidence`，前端只能通过引用数量或正文间接判断 |
| 修复动作 | `get_chat_messages()` 对 assistant 历史消息补充 `insufficient_evidence` 字段；无引用回答返回 `true`，有引用回答返回 `false` |
| 前端同步 | `KnowledgeBaseChatPanel` 恢复历史问答时优先使用后端 `insufficient_evidence`，不再只依赖 `has_citations` 与引用数组推断 |
| 验收锁定 | 新增无依据问题测试，验证回答正文包含“证据不足，不能下确定性法律结论”和“无可用引用来源”，历史消息保留 `insufficient_evidence = true`、`citations = []`、`has_citations = 0` |
| 验证结果 | `test_m24_knowledge_base_data_plane.py` 共 19 个用例通过；Agent Console TypeScript 检查通过 |

该补强后，P0-05 的“历史问答保留回答与引用关系或缺失提示”不再只依赖正文解析，后端历史消息、前端状态恢复和测试断言均具备明确字段。

## 3.3 2026-06-02 P0-06 联调记录

本轮继续推进 `V5-P0-006 权限隔离基础模型`，重点补强“可查看资料不等于可调用 AI”的权限红线。

| 项目 | 处理结果 |
|---|---|
| 已确认覆盖 | 客户、案件、部门、项目组字段已在知识库模型中预留；ACL 继承、临时授权过期、客户/案件/部门/项目组边界和 Ethical Wall 基础已有测试覆盖 |
| 发现缺口 | 现有测试覆盖了 view/preview 权限隔离，但缺少对 `ai_query` 单独拒绝后的检索与生成阻断断言 |
| 补强动作 | 新增 `test_ai_query_permission_denial_blocks_retrieval_and_generation`，构造用户仍可 view 知识库和文件，但在知识库层 deny `ai_query` 的场景 |
| 验收锁定 | deny `ai_query` 后，`effective_permissions` 中 `view = true`、`ai_query = false`；底层 `Store.search()` 返回空；`ask_knowledge_base()` 抛出权限错误 |
| 验证结果 | `test_m24_knowledge_base_data_plane.py` 共 20 个用例通过 |

该补强后，P0-06 的“无权限用户不能查看、编辑或调用知识库”被细化到 AI 调用维度，避免用户拥有资料查看权时绕过 ACL 调用 RAG 检索或生成。

## 4. 后续开发顺序

| 顺序 | 开发项 | 说明 |
|---:|---|---|
| 1 | 文件级治理元数据 | 将知识类型、审核状态和 AI 使用规则从知识库扩展到文件 |
| 2 | 审核动作 API | 新增提交审核、通过、退回、废止、标记需更新接口 |
| 3 | 审核日志 | 审核动作写入本地审计日志，支持按知识库追溯 |
| 4 | 结构化法律回答 | RAG 回答模板升级为结论、依据、引用、前提、风险、不确定事项、下一步 |
| 5 | 过期知识处理 | 到期知识提示维护，默认不作为正式生成依据 |
| 6 | 管理看板指标 | 汇总知识贡献、使用、过期、证据不足率和差评问题 |

## 5. 第一阶段验收清单

| 类别 | 验收项 |
|---|---|
| 知识治理 | 管理员可创建法规库、案例库、模板库、条款库等不同知识类型 |

| 权限 | 无 `ai_query` 权限用户仍不能绕过治理策略提问 |

| 前端 | 知识库工作台可展示并编辑治理配置 |
