# V4.1 PRD：MVP 压缩版 - 律师本地数据主权型 AI 案件知识库工作台

> 基于 V4 PRD 评审会议结论压缩  
> 版本定位：先验证 Agent 本地知识库闭环与平台不可见  
> 文档类型：MVP 产品需求文档  
> 版本：V4.1  
> 日期：2026-05-22

---

## 1. 文档说明

### 1.1 文档目的

V4 PRD 已定义完整产品愿景：

```text
平台控制平面
+ 律师侧 Agent 数据平面
+ 本地数据库连接器
+ 本地 RAG 问答
+ 四端后台体系
```

但评审会议一致认为，V4 完整版范围过大，不适合直接作为 MVP 开发范围。

本文档用于定义 V4.1 MVP 压缩版，只保留最关键的可交付闭环：

```text
Agent 本地部署
-> 本地资料入库
-> 本地解析和向量化
-> 本地案件问答带来源
-> 平台不可见律师业务数据
```

### 1.2 会议结论摘要

| 结论 | 说明 |
|---|---|
| V4 方向正确 | 本地 Agent + 平台不可见更适合法律行业 |
| MVP 必须收窄 | 不能一开始完整实现律所知识平台 |
| 平台不可见是红线 | 必须技术可证明、测试可验证 |
| 数据库连接器重要但复杂 | MVP 可做极简版或作为 MVP+ 第二迭代 |
| 四端后台保留方向 | MVP 只做最小菜单和最小权限 |
| 安全合规不是后置 | 平台不可见、凭证本地加密、数据库只读、审计日志是 P0 |

### 1.3 V4.1 产品目标

V4.1 的目标不是完整交付所有律师 AI 能力，而是证明以下命题：

```text
律师可以在自己的服务器上部署 Agent，
把本地案件资料建立为 AI 知识库，
完成带来源的案件问答，
且平台完全看不到律师业务数据。
```

## 2. MVP 产品定位

### 2.1 MVP 一句话定义

```text
一个部署在律师本地的案件资料 AI 问答助手，平台只负责授权和脱敏健康状态，不能看到任何律师业务数据。
```

### 2.2 MVP 不做什么

V4.1 MVP 不做：

| 不做内容 | 原因 |
|---|---|
| 完整工单系统 | 先用脱敏诊断包导出替代 |
| 数据不可见审计面板 | P1 做，MVP 先做白名单和测试验证 |
| 多 Agent 管理 | 先跑通单 Agent |
| 团队知识审核流 | MVP 先做个人/小团队案件工作台 |
| 完整文书生成 | 法律风险高，先做证据目录和案件摘要 |
| 类案报告 | 依赖历史数据质量，后置 |
| 移动端 | PC Web 优先 |
| 公共法规库 | 数据源和合规复杂，后置 |
| 平台托管模型 | 破坏平台不可见定位，不做 |
| 普通用户开放问答 | 合规风险高，MVP 不做 |
| CDC 数据同步 | 技术复杂，MVP 不需要 |
| SQL Server/Oracle | 先支持 MySQL/PostgreSQL 或后置 |

## 3. MVP 主链路

### 3.1 核心闭环

```text
Agent 安装
-> 授权激活
-> 本地目录接入
-> 创建案件
-> 文件解析
-> 向量化
-> 案件问答
-> 来源引用
-> 平台脱敏健康状态
```

### 3.2 MVP+ 可选闭环

数据库连接器建议作为 MVP+，即第一版开发完成后紧接着做的增强闭环：

```text
数据库只读连接
-> 表/视图选择
-> 字段映射
-> 手动同步
-> 生成案件候选记录
-> 关联本地文件路径
```

如果开发资源充足，可纳入 MVP；如果资源紧张，放入第二迭代。

## 7. 平台不可见红线

以下任一情况出现，MVP 不得上线：

| 红线 | 说明 |
|---|---|
| 平台数据库出现业务数据 | 包括案件名、文件名、正文、问答、向量、数据库字段值 |
| 健康上报出现业务字段 | 白名单外字段即 P0 问题 |
| 平台日志出现文件名/案件名 | 说明日志脱敏失败 |
| 数据库连接器可执行写入 SQL | 违反只读原则 |
| 模型 API Key 上传平台 | 违反本地凭证原则 |
| 平台可查看问答正文 | 违反平台不可见承诺 |
| 平台可访问文件预览 | 违反平台不可见承诺 |
| 平台可执行远程 SQL | 违反数据库安全原则 |

## 8. Agent 部署前置条件

### 8.1 MVP 支持环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux 优先 |
| 部署方式 | Docker Compose |
| CPU | 建议 4 核及以上 |
| 内存 | 建议 8GB 及以上 |
| 磁盘 | 视文件量而定，建议至少 100GB 可用空间 |
| 网络 | 能访问模型 API 或本地模型服务 |
| 浏览器 | Chrome / Edge / Safari 最新版 |
| 数据库 | MVP+ 支持 MySQL/PostgreSQL |

### 8.2 服务端口建议

| 服务 | 端口 | 说明 |
|---|---|---|
| Agent API | 8000 | 本地 API 服务 |
| Agent Web | 3000 | 本地管理台和案件工作台 |
| Qdrant | 6333 | 本地向量库 |
| Redis | 6379 | 本地任务队列，可仅内网访问 |
| PostgreSQL | 5432 | 本地元数据库，可选 |

### 8.3 部署前检查项

```text
Docker 是否可用
Docker Compose 是否可用
目标目录是否可读写
本地磁盘是否足够
模型 API Key 是否准备
是否允许访问模型供应商
是否需要内网访问
数据库只读账号是否准备
数据库只读视图是否准备
```

## 9. 错误码规范

MVP 禁止向平台上传自由文本业务错误，只允许标准错误码。

| 错误码 | 含义 | 是否可上报平台 |
|---|---|---|
| AGENT_OFFLINE | Agent 离线 | 是 |
| AGENT_AUTH_FAILED | Agent 授权失败 | 是 |
| DIR_PERMISSION_DENIED | 本地目录无权限 | 是 |
| FILE_PARSE_FAILED | 文件解析失败 | 是 |
| OCR_FAILED | OCR 失败 | 是 |
| VECTOR_INSERT_FAILED | 向量写入失败 | 是 |
| LLM_TIMEOUT | 模型响应超时 | 是 |
| LLM_AUTH_FAILED | 模型认证失败 | 是 |
| DB_CONN_FAILED | 数据库连接失败 | 是 |
| DB_AUTH_FAILED | 数据库认证失败 | 是 |
| DB_READONLY_REQUIRED | 数据库账号非只读 | 是 |
| UNKNOWN_ERROR | 未知错误 | 是，但不得附带业务文本 |

平台不得接收：

```text
解析 张三合同纠纷.pdf 失败
案件 李四离婚案 同步失败
数据库 case_name 字段为空
问题 “这个案件胜诉概率如何” 生成失败
```

## 10. 脱敏诊断包规范

### 10.1 允许包含

```text
Agent 版本
操作系统类型
Docker 版本
服务状态
资源使用率
标准错误码
任务数量
最近失败任务 ID
队列长度
模型服务连通性状态
数据库连通性状态
```

### 10.2 禁止包含

```text
案件名
文件名
文件路径
数据库表内容
数据库字段值
问题文本
答案文本
原文片段
文书内容
律师笔记
模型 API Key
数据库密码
SSH Key
```

### 10.3 诊断包流程

```text
Agent 本地生成诊断包
-> 律师/Agent 管理员预览诊断包内容
-> 系统标记是否包含敏感字段
-> 用户确认导出
-> 用户主动发送给平台支持
```

| SA-002 | 健康上报白名单 | 上报字段全部在白名单内 |

| SA-004 | 凭证安全 | 模型 API Key、数据库密码不上传平台 |
| SA-005 | 本地权限 | 未授权用户无法访问案件 |
| SA-006 | SQL 只读 | MVP+ 数据库连接器不能执行写入 SQL |
| SA-007 | 诊断包脱敏 | 诊断包不包含业务内容和凭证 |

### 11.3 体验验收

| 编号 | 验收项 | 标准 |
|---|---|---|
| UX-001 | 首个案件入库 | Agent 部署后 30 分钟内完成首个案件入库 |
| UX-002 | 状态可见 | 文件解析、OCR、向量化状态清晰 |
| UX-003 | 错误可理解 | 目录权限、解析失败、模型失败有明确提示 |
| UX-004 | 问答可信 | 关键回答有来源或明确标记无依据 |
| UX-005 | 边界清晰 | 用户能理解哪些页面在平台，哪些页面在本地 Agent |

## 14. 最终结论

V4.1 MVP 的核心不是做完整律师 AI 平台，而是验证：

```text
Agent 本地知识库闭环
+ 平台不可见律师业务数据
+ 本地案件问答带来源
```

MVP 只要把以下链路做稳，就具备试点价值：

```text
律师部署 Agent
-> 接入本地目录
-> 创建案件
-> 解析案件材料
-> 建立本地向量库
-> 基于案件材料问答
-> 回答带来源
-> 平台只看到脱敏健康状态
```

后续再逐步扩展：

```text
数据库连接器
律所团队知识库
文书草稿
类案检索
工单支持
数据不可见审计面板
```

一句话总结：

```text
先证明平台看不到、Agent 跑得动、问答有来源，再做更复杂的律所知识平台。
```
