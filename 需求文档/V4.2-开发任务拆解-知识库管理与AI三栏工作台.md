> 日期：2026-05-29

---

## 1. 研发总目标

V4.2 研发目标不是推翻 V4.1，而是在现有 Agent 本地数据主权、案件、文件处理、RAG、引用、安全边界基础上，新增一层知识库业务抽象。

核心闭环：

```text
创建私人/团队/案件知识库
-> 上传或导入文件
-> 目录化和标签化管理
-> 按组织、角色、知识库、目录、文件、操作授权
-> 文件解析、OCR、向量化
-> 三栏工作台预览文件并 AI 问答
-> AI 回答带引用并跳转原文
-> 提示词和 skills 可管理
-> 全过程本地审计且平台不可见业务数据
```

## 10. EP5：AI 上下文和 RAG 改造

### 10.1 目标

把现有案件 RAG 升级为支持当前文件、选中文本、目录、知识库、案件、跨库的上下文问答。

### 10.2 后端任务

| ID | 任务/API | 说明 | 验收标准 |
|---|---|---|---|
| EP5-001 | 定义上下文模型 | `context_scope` | 支持 selected_text/current_file/current_folder/current_kb/current_case |
| EP5-002 | 新增 AI 查询接口 | `POST /api/agent/ai/query` | 根据上下文检索和回答 |
| EP5-003 | 当前文件问答 | `current_file` | 只检索当前文件切片 |
| EP5-004 | 当前目录问答 | `current_folder` | 只检索目录及子目录文件 |
| EP5-005 | 当前知识库问答 | `current_kb` | 只检索知识库内有权文件 |
| EP5-006 | 当前案件问答 | `current_case` | 兼容原案件 RAG |
| EP5-007 | 选中文本动作 | `POST /api/agent/ai/selected-text/actions` | 支持解释、总结、提取证据、生成引用 |
| EP5-008 | 引用结构扩展 | 文件、页码、段落、chunk、预览定位 | 前端可跳转定位 |
| EP5-009 | 无依据提示 | 检索为空或低置信 | 返回明确无依据提示 |
| EP5-010 | 对话历史扩展 | `ai_conversations` | 保存上下文范围和关联资源 |

### 10.3 AI 规则

| 规则 | 验收标准 |
|---|---|
| 不越权 | 检索和引用均不得包含无权限文件 |
| 不编造 | 无依据时必须提示未找到授权资料依据 |
| 可核验 | 每条关键结论尽量绑定引用 |
| 可追溯 | 对话、检索范围、skill 调用写入本地审计 |

| P0 | EP3-001 至 EP3-006 | 文件树、目录、上传到知识库/目录 |
| P0 | EP4-001、EP4-006 | 权限动作枚举和后端权限检查函数 |

### 17.2 Sprint 1 不做

| 不做 | 原因 |
|---|---|
| 完整三栏工作台 | 依赖文件树、预览、AI 上下文接口 |
| 外部组织同步 | 先完成手动组织和权限底座 |
| 自定义 skills | 依赖 AI 上下文和 prompt 模板 |
| Excel 高级预览 | 非 MVP 主链路 |

### 17.3 Sprint 1 验收口径

```text
用户可以创建私人/团队知识库；
创建案件时系统自动生成案件知识库；
用户可以在知识库内新建目录并上传文件；
文件归属到 knowledge_base_id + folder_id；
无权限用户不能访问知识库详情和文件详情；
原 V4.1 登录、案件、上传、RAG smoke test 不回退。
```

## 18. 风险控制

| 风险 | 控制方式 |
|---|---|
| 范围失控 | MVP 只保留三类知识库、文件、权限、三栏 AI、prompt/skills 基础 |
| 破坏 V4.1 | EP0 先做回归保护，旧 API 保留兼容 |
| ACL 复杂 | 先做 P0 操作权限，审批、分享、彻底删除 P1 |
| AI 越权 | AI 检索前过滤，引用返回前二次校验 |
| 组织同步延期 | 手动组织 P0，首个外部连接器 P0/P1 边界可控 |
| 文件预览复杂 | 首版 PDF、Word 转文本、图片、TXT，Excel 高级能力 P1 |
| 平台不可见被破坏 | 自动化测试检查平台接口、日志、诊断包 |

## 19. 小P排期结论

V4.2 的开发顺序必须是：

```text
先数据底座
再文件和权限
再 AI 上下文
再三栏工作台
再组织同步和 Prompt/Skills
最后补搜索、审计和验收
```

不能先做漂亮的三栏 UI，否则会因为缺少知识库、文件归属和权限模型，后面返工严重。

第一轮研发任务应锁定在 Sprint 1：

```text
V4.1 回归保护
+ 知识库/目录/文件归属模型
+ 知识库基础 API
+ 文件树和上传 API
+ 基础权限检查
+ 案件自动知识库
```

这一轮完成后，前端即可开始搭建三栏工作台骨架，后端同步推进 AI 上下文和 ACL 完整化。
