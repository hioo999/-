# V5 第一阶段会议决议：部门级试点范围冻结

> 项目：律师本地数据主权型 AI 案件知识库工作台  
> 会议角色：产品经理小P主持，全体角色会审  
> 决议日期：2026-06-01  
> 决议目标：统一第一阶段交付口径，避免在 POC、V4.2 MVP 和 V5 全所级中台之间继续摇摆

---

## 1. 会议结论

第一阶段不按“大型律所全所级知识中台”承诺交付。

第一阶段统一定义为：

```text
部门级本地知识库 AI 工作台试点版
```

本阶段目标是在现有 V4.1 MVP M25 工程基线基础上，吸收 V4.2 的知识库与三栏工作台能力，并从 V5 中只选择最关键的 P0 治理能力，完成一个可部署、可演示、可验收、可复盘的部门级试点闭环。

---

## 2. 阶段定位

| 项目 | 决议 |
|---|---|
| 当前工程基线 | V4.1 MVP M25 |
| 当前产品目标 | 部门级知识库 AI 工作台试点 |
| 目标用户 | 1 个业务部门或 1 个律师团队 |
| 试点人数 | 20-50 人作为产品目标；如按 POC 报价执行，则压缩为 3-5 名核心测试用户 |
| 试点知识库 | 3-5 个典型知识库 |
| 核心验证 | 本地数据闭环、知识治理、权限隔离、AI 引用、拒答、质量反馈 |
| 不承诺范围 | 全所级中台、SSO、OA/DMS/案件系统深度集成、Ethical Wall 完整模型 |

---

## 3. 范围口径

### 3.1 必须纳入第一阶段

| 范围 | 说明 |
|---|---|
| Agent 本地部署 | 继续坚持律师侧本地处理数据 |
| 平台不可见 | 平台不得接收案件、文件、问答、向量、Prompt、模型密钥等业务数据 |
| 知识库管理 | 支持部门级试点所需的知识库创建、配置、文件入库和检索 |
| 三栏式工作台 | 左侧知识库/文件树，中间文件或详情区，右侧 AI 对话区 |
| 知识分类 | 支持法规、案例、模板、条款、文书、培训、复盘、客户行业、部门专业、案件专属等类型 |
| 治理元数据 | 支持审核状态、维护人、有效期、保密等级、AI 使用规则、引用优先级 |
| AI 使用范围控制 | 支持允许生成、仅检索不可生成、禁止 AI 使用 |
| 来源引用 | AI 回答必须尽量返回来源，证据不足时明确提示 |
| 权限隔离基础 | 基于现有 ACL，预留客户、案件、部门、项目组维度 |
| 质量反馈闭环 | 记录差评原因、引用缺失、证据不足等质量问题 |
| 交付验证 | 保留平台不可见报告、交付包边界校验、泄漏扫描、验收证据报告 |

### 3.2 暂不纳入第一阶段

| 暂缓项 | 暂缓原因 |
|---|---|
| 全所级知识中台 | 超出部门级试点目标 |
| 完整 SSO | 依赖客户身份系统，试点阶段先不绑定 |
| OA/DMS/案件系统集成 | 依赖外部系统接口与数据治理，后置 |
| Ethical Wall / Chinese Wall 完整能力 | 需要更复杂的客户墙、利益冲突和组织策略 |
| 外部协作人临时权限 | 涉及外部访问、水印、审批、脱敏策略，后置 |
| 离职/转岗权限自动回收 | 依赖组织同步和 HR/OA 数据源，后置 |
| 全所级管理看板 | 第一阶段只保留 P0 指标，不做全量经营分析 |
| 数据库连接器 | 维持 MVP+ 后续范围，不进入第一阶段承诺 |
| 在线协同编辑 | 文件协同编辑复杂度高，暂不纳入 |

---

## 4. 商务与交付边界

当前成本估算 V4 的报价口径为第一期 POC，周期 4-6 周，费用 4-5 万元，核心范围为文件上传、文档解析、知识库入库、AI 问答、引用来源、后台管理、单机部署。

本次会议决议明确：

| 情况 | 执行口径 |
|---|---|
| 若仍按 4-5 万 POC 报价执行 | 仅承诺 POC 核心闭环，试点人数压缩为 3-5 名，V5 治理能力只做最小版本 |
| 若按部门级试点版执行 | 需单独评估知识治理、三栏工作台、权限隔离、质量反馈和交付验收的追加工作量 |
| 若客户要求全所级中台 | 必须另立 V5 全量项目，不沿用 POC 报价和周期 |

---

## 5. 第一阶段成功标准

第一阶段成功不以“功能多”为标准，而以“能否支撑真实部门试点”为标准。

| 类别 | 成功标准 |
|---|---|
| 数据主权 | 文件、问答、向量、模型密钥仍留在律师侧 Agent 本地 |
| 知识治理 | 至少 3 类知识库能配置类型、状态、维护人、密级和 AI 使用策略 |
| AI 风控 | 无依据时拒答或提示证据不足；禁止 AI 的知识库不参与生成 |
| 权限 | 非授权用户不能绕过 ACL 查看、检索或生成回答 |
| 引用 | 有效回答可追溯到来源材料 |
| 反馈 | 差评、引用缺失、证据不足能进入统计或待处理清单 |
| 交付 | 交付包、验收报告和平台不可见报告可复验 |

## 6. 角色分工

| 角色 | 第一阶段责任 |
|---|---|
| 产品经理小P | 冻结范围，维护需求清单、验收标准和变更记录 |

| 安全工程师 | 验证平台不可见、凭证本地化、诊断脱敏和交付边界 |
| 测试工程师 | 将本决议转为功能、安全、权限、AI 风控、交付验收用例 |
| 交付/运维 | 固化部署脚本、客户环境检查、交付包和复验流程 |
| 商务/负责人 | 确认 POC 报价与部门级试点范围是否匹配 |

| 顺序 | 动作 | 输出物 |

---

## 8. 变更控制

以下事项如果新增，必须走范围变更：

- 增加全所级推广能力
- 增加 OA、DMS、案件系统、SSO 集成
- 增加数据库连接器
- 增加外部协作人访问
- 增加完整 Ethical Wall / Chinese Wall
- 增加在线协同编辑
- 增加移动端或小程序端
- 要求平台侧查看任何律师业务数据

任何变更不得突破“平台不可见律师业务数据”的底线。
