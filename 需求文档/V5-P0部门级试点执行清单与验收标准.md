# V5 P0 部门级试点执行清单与验收标准

> 承接文档：`V5-第一阶段会议决议-部门级试点范围冻结.md`  
> 产品基线：V4.1 MVP M25 + V4.2 知识库与三栏工作台方向 + V5 P0 治理能力  
> 角色视角：产品经理小P  
> 日期：2026-06-01

---

## 1. 执行目标

本清单用于把第一阶段“部门级本地知识库 AI 工作台试点版”转化为可排期、可开发、可测试、可验收的 P0 任务。

本阶段只追求一个真实可用的试点闭环：

```text
知识库配置 -> 文件入库 -> 权限校验 -> AI 检索/回答 -> 来源引用 -> 风控拒答 -> 质量反馈 -> 交付验收
```

## 3. 详细任务拆解

### P0-01 V4.1 M25 基线冻结

目标：确认现有工程能力不被 V5 P0 改造破坏。

| 子任务 | 验收口径 |
|---|---|
| 回归 Agent 本地登录、案件、文件、任务、RAG、模型配置 | 现有 API 回归测试通过 |
| 回归案件成员权限 | 非成员访问案件、文件、任务、RAG 被拒绝 |
| 回归平台不可见 | 平台接口、日志、报告不出现业务字段 |
| 回归交付脚本 | 交付包边界、泄漏扫描、验收报告可运行 |

完成标准：V5 P0 开发前形成一次基线验证记录。

---

### P0-02 试点知识库分类体系

目标：让部门试点不再只按“普通文件夹”管理知识，而能表达律师知识资产类型。

第一阶段支持以下类型：

| 类型 | 使用场景 |
|---|---|
| 法规库 | 法规、司法解释、规范性文件 |
| 案例库 | 裁判案例、类案材料 |
| 模板库 | 合同模板、文书模板、法律意见书范本 |
| 条款库 | 合同条款、风险条款、替代条款 |
| 文书库 | 起诉状、答辩状、代理词、律师函等 |
| 培训库 | 内训材料、课程资料、青年律师培训 |
| 复盘库 | 项目复盘、案件复盘、经验总结 |
| 客户行业库 | 行业研究、客户背景、交易惯例 |
| 部门专业库 | 部门专业文章、办案指引、标准流程 |
| 案件专属库 | 单案件资料、证据、沟通材料 |

验收标准：

| 验收项 | 标准 |
|---|---|
| 创建知识库 | 管理员能选择知识类型 |
| 编辑知识库 | 管理员能修改知识类型 |
| 展示知识库 | 前端能展示类型标签 |
| 检索兼容 | 原有 RAG 检索不因类型字段失败 |
| 老数据兼容 | 老知识库有默认类型，不丢失数据 |

---

### P0-03 知识治理元数据

目标：让知识库具备最小治理能力，支持部门试点中的审核、维护和 AI 使用边界。

字段要求：

| 字段 | 第一阶段要求 |
|---|---|
| 审核状态 | 草稿、待审核、已发布、已退回、已废止、需更新、禁止 AI 使用 |
| 维护人 | 支持指定维护人或维护账号 |
| 有效期 | 支持设置到期日期，过期后提示维护 |
| 保密等级 | 公开、内部、敏感、高敏 |
| AI 使用规则 | 允许生成、仅检索不可生成、禁止 AI 使用 |
| 引用优先级 | 高、中、低，影响引用排序或后续排序策略 |

验收标准：

| 验收项 | 标准 |
|---|---|
| 新建配置 | 新建知识库时可配置治理字段 |
| 编辑配置 | 已有知识库可修改治理字段 |
| 默认值 | 老数据自动补默认值 |
| 前端展示 | 知识库详情可展示治理信息 |
| 审计记录 | 关键治理字段变更进入本地审计或操作记录 |

---

### P0-04 AI 使用范围控制

目标：防止所有知识默认进入 AI 生成范围。

策略规则：

| 策略 | 行为 |
|---|---|
| 允许生成 | 可检索，可进入 AI 回答生成 |
| 仅检索不可生成 | 可展示检索命中，但不能让模型基于该知识生成确定性回答 |
| 禁止 AI 使用 | 不进入检索，不进入生成，不作为引用来源 |

验收标准：

| 验收项 | 标准 |
|---|---|
| 允许生成 | 正常检索并生成回答 |
| 仅检索 | 能看到命中提示，但生成时返回受控拒答 |
| 禁止 AI | 检索和生成均不使用该知识库 |
| 权限叠加 | 无 `ai_query` 权限用户不能绕过策略 |
| 日志 | 受控拒答原因可记录为非业务正文的事件类型 |

---

### P0-05 引用与证据不足拒答

目标：法律 AI 不能输出无依据的确定性结论。

回答结构最小要求：

```text
1. 简要结论
2. 依据来源
3. 适用前提
4. 风险提示
5. 证据不足或需补充材料
```

验收标准：

| 验收项 | 标准 |
|---|---|
| 有依据回答 | 返回结论和来源引用 |
| 无依据问题 | 明确提示未找到充分依据，不编造结论 |
| 引用展示 | 前端能展示来源文件或片段信息 |
| 历史记录 | 历史问答保留回答与引用关系或缺失提示 |
| 反馈入口 | 用户可标记引用缺失、答案不准确、证据不足 |

---

### P0-06 权限隔离基础扩展

目标：在现有 ACL 基础上，为大所后续权限模型预留基础维度。

第一阶段只做基础模型，不做完整 Ethical Wall。

| 维度 | 第一阶段要求 |
|---|---|
| 客户 | 字段预留，可在知识库或案件上标记 |
| 案件 | 继续复用现有案件成员权限 |
| 部门 | 字段预留，可标记知识库所属部门 |
| 项目组 | 字段预留，可支持后续项目组 ACL |

验收标准：

| 验收项 | 标准 |
|---|---|
| 非成员隔离 | 非成员不能访问案件资料或基于案件资料问答 |
| 知识库权限 | 无权限用户不能查看、编辑或调用知识库 |
| 字段保留 | 客户、部门、项目组字段不影响现有接口 |
| 安全测试 | 构造越权请求时返回拒绝 |

---

### P0-07 三栏式知识库工作台

目标：让部门试点用户在一个界面完成找资料、看资料、问 AI、看引用。

页面结构：

| 区域 | 功能 |
|---|---|
| 左侧 | 知识库列表、文件树、类型和状态筛选 |
| 中间 | 文件详情、知识库治理配置、入库状态、引用片段 |
| 右侧 | AI 对话、引用来源、拒答原因、反馈入口 |

验收标准：

| 验收项 | 标准 |
|---|---|
| 基础导航 | 用户可在知识库、文件、AI 对话之间切换 |
| 治理可见 | 用户能看到知识库类型、状态、密级、AI 策略 |
| 权限态展示 | 无权限、被撤权、禁止 AI 使用有明确提示 |
| 响应式 | 桌面可用，窄屏不阻塞核心操作 |

---

### P0-08 质量反馈闭环

目标：让试点阶段能发现 AI 问答质量问题，而不是只看能否回答。

反馈类型：

| 类型 | 说明 |
|---|---|
| 引用缺失 | 回答未给出来源或来源不足 |
| 答案不准确 | 用户认为结论或表述存在错误 |
| 证据不足 | 系统应拒答但给出了结论，或材料不足 |
| 权限异常 | 用户看到不应看到的资料或回答 |
| 其他 | 用户自定义备注 |

验收标准：

| 验收项 | 标准 |
|---|---|
| 提交反馈 | 用户可对回答提交反馈类型和备注 |
| 反馈记录 | 后端保存反馈记录并关联问答或知识库 |
| 统计口径 | 管理员可查看差评数量、引用缺失、证据不足数量 |
| 隐私边界 | 反馈统计给平台时不得包含业务正文 |

---

### P0-09 交付验收包

目标：保证客户拿到的不是散乱代码，而是可复验的试点交付包。

交付内容：

| 交付物 | 要求 |
|---|---|
| 源代码与部署脚本 | 只包含允许交付的工程文件 |
| 部署说明 | 说明 Agent、平台、模型、向量库、OCR 的配置方式 |
| 验收报告 | 使用 `m21-delivery-acceptance-report-v2`，包含功能、安全、权限、AI 风控、交付包检查结果和 V5 P0 专项证据摘要 |
| 平台不可见报告 | 证明平台侧不接收律师业务数据 |
| 交付包校验 | 包含边界校验、泄漏扫描、SHA-256 完整性校验 |
| Bundle manifest | 使用 `m21-delivery-bundle-v2`，记录验收报告 schema、通过状态、metadata-only 标志和 V5 P0 证据项名称 |

验收标准：

| 验收项 | 标准 |
|---|---|
| 交付包边界 | 不包含 `.venv`、`node_modules`、本地数据库、私有 env、日志、样本文档 |
| 泄漏扫描 | 不包含 API Key、私钥、真实案情、文件正文、问答正文 |
| 验收报告 | 报告为 metadata-only，不包含业务字段 |
| V5 P0 证据 | 验收报告必须覆盖知识治理、AI 风控、质量反馈、历史引用、平台不可见专项检查和交付红线六类证据 |
| Manifest 一致性 | bundle manifest 中的 V5 P0 证据摘要必须与验收报告一致 |
| 红线扫描 | 验收报告必须通过业务字段红线扫描，拒绝 `file_name`、`file_path`、`chunk_text`、`question`、`answer`、`api_key`、`prompt` 等字段 |
| 解包复验 | 客户可在解包目录内执行基础复验 |

专项证据项：

| 证据项 | 覆盖范围 |
|---|---|
| `knowledge_governance_metadata_and_audit` | 知识治理元数据、审核流转、分离审核、部门管理员审核、治理审计 |
| `ai_risk_controls_and_policy_enforcement` | 仅检索、禁止 AI、过期、高敏自动禁用、证据不足拒答和结构化风险提示 |
| `quality_feedback_closed_loop` | 反馈绑定真实回答、问题标签归一化、处理状态、管理统计 |
| `historical_citation_and_source_traceability` | 知识库范围内检索、历史引用恢复、来源可追溯、引用优先级和可信度 |
| `platform_invisibility_special_checks` | 平台无业务表/字段、控制面白名单、禁止业务字段探针、平台控制台不可见 smoke |
| `delivery_acceptance_package_redaction` | 交付包边界、泄漏扫描、checksum、解包 smoke、验收报告红线扫描 |

## 5. 验收样本建议

| 项目 | 建议标准 |
|---|---|
| 试点用户 | 部门级试点 20-50 人；POC 报价口径压缩为 3-5 人 |
| 知识库 | 3-5 个 |
| 文件 | POC 为 100-300 份；部门试点可扩展到 500-2000 份 |
| 测试问题 | POC 为 30-50 个；部门试点建议 100 个以上 |
| 角色 | 主办律师、协办律师、律师助理、部门管理员、Agent 管理员 |
| 试用时间 | POC 1 周；部门试点建议 2-4 周 |

## 6. 必测场景

| 场景 | 必测点 |
|---|---|
| 普通问答 | 有来源回答，引用可追溯 |
| 无依据问题 | 不编造，提示证据不足 |
| 仅检索知识库 | 命中可提示，但不能生成确定性结论 |
| 禁止 AI 知识库 | 不检索、不生成、不引用 |
| 权限撤销 | 撤权后不能继续访问或问答 |
| 高敏知识 | 高敏或禁止 AI 策略生效 |
| 反馈提交 | 用户能提交质量反馈 |
| 平台不可见 | 平台侧报告和接口不出现业务数据 |
| 交付包 | 不包含运行时数据、密钥、样本文档 |

---

## 7. 退出条件

以下任一情况出现，不允许进入试点验收：

- 平台侧能看到案件名、文件名、正文、问答、向量或 Prompt
- 非授权用户能访问案件、知识库、文件或 RAG 回答
- 禁止 AI 的知识库仍被模型使用
- 无依据问题仍输出确定性法律结论
- 交付包包含本地数据库、私有环境变量、样本文档或密钥
- 核心流程无法完成文件入库、检索、问答、引用、反馈闭环

## 8. 后续升级入口

第一阶段通过后，再进入 V5 后续范围：

| 后续方向 | 触发条件 |
|---|---|
| SSO | 试点部门确认扩大到多部门 |
| OA/DMS/案件系统集成 | 客户提供稳定接口和字段说明 |
| Ethical Wall | 客户明确客户墙和利益冲突规则 |
| 数据库连接器 | 客户需要接入现有案件库或文档库 |
| 全所级管理看板 | 管理层开始关注知识贡献、复用和风险态势 |
| 外部协作人 | 出现客户、专家、外部律师参与场景 |

本清单不替代 V5 全量 PRD，只作为第一阶段部门级试点的执行边界。
