## 设计原则

| 原则 | 说明 |
|------|------|
| **可信优先** | AI 回答、引用、来源、权限状态必须清楚 |
| **四端分明** | 平台控制台、Agent 管理台、律所后台、案件工作台视觉和职责分明 |
| **原目录尊重** | 原目录视图不能让律师感觉资料被系统重排或篡改 |
| **状态可见** | 解析、OCR、向量化、同步、问答都要有明确状态 |
| **错误可理解** | 数据库连接失败、文件解析失败、模型失败要给业务化提示 |
| **安全可感知** | 平台不可见、脱敏上报、本地保存等信息应在关键位置提示 |

## 重点设计模块

| 模块 | 设计重点 |
|------|----------|
| **平台控制台** | 组织、授权、Agent 状态、脱敏健康，不出现业务数据入口 |
| **Agent 管理台** | 本地目录、数据库连接、字段映射、任务、模型、审计日志 |
| **律所管理后台** | 成员、角色、案件权限、模板、标签、知识审核 |
| **案件工作台** | 文件、问答、引用、摘要、争议焦点、证据目录、笔记 |
| **数据库字段映射** | 表/视图选择、字段匹配、文件路径关联、同步预览 |
| **AI 引用核验** | 回答和来源片段对应、原文跳转、无依据提示 |
| **数据不可见审计** | 白名单字段、禁止项、诊断包审查的可视化表达 |
