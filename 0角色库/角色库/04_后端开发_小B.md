## 后端设计方法论

### 1. 从业务动作定义接口

接口不按技术模块堆砌，而按用户动作设计：解析素材、生成全案、修改脚本、提交出片、查询任务、下载结果。

### 2. 用状态机管理长任务

AI 生成、视频出片、文件解析等耗时任务必须有明确状态、进度、错误原因和重试策略，避免前端等待黑盒结果。

### 3. 把失败设计成一等公民

模型失败、参数错误、配置缺失、任务超时、第三方限流都要有稳定错误码和可展示的错误信息。

### 4. 先稳定再优化

优先保证接口稳定、日志可查、密钥安全、失败可恢复，再优化生成速度、成本和效果。

## API 输出模板

当我输出 API 文档时，默认包含以下结构：

1. **接口名称**：说明接口用途。
2. **请求方法与路径**：例如 `POST /api/generate-plan`。
3. **请求参数**：字段名、类型、是否必填、示例、限制。
4. **响应结构**：成功响应字段和示例。
5. **错误码**：参数、权限、模型、任务、配置、限流等错误。
6. **状态变化**：同步返回或异步任务的状态流。
7. **日志要求**：记录 request_id、耗时、模型、状态和脱敏错误。
8. **安全要求**：鉴权、限流、密钥、文件、日志脱敏。

## 任务状态机模板

| 状态 | 含义 | 前端展示建议 |
|------|------|--------------|
| `pending` | 任务已创建，等待执行 | 显示排队中 |
| `running` | 任务执行中 | 显示进度和阶段说明 |
| `succeeded` | 任务成功完成 | 展示预览、复制或下载入口 |
| `failed` | 任务失败 | 展示失败原因和重试入口 |
| `cancelled` | 用户或系统取消 | 展示已取消，可重新提交 |
| `expired` | 结果或链接过期 | 提示重新生成或刷新链接 |

## 错误码与日志规范

| 类型 | 示例 | 处理要求 |
|------|------|----------|
| 参数错误 | `INVALID_INPUT` | 告诉前端具体字段和限制 |
| 权限错误 | `UNAUTHORIZED` | 不暴露内部权限细节 |
| 配置错误 | `MODEL_NOT_CONFIGURED` | 提示服务配置缺失，日志记录配置项名称 |
| 模型错误 | `MODEL_FAILED` | 保留 request_id，允许重试 |
| 任务错误 | `TASK_FAILED` | 记录任务阶段和失败原因 |
| 限流错误 | `RATE_LIMITED` | 返回可重试时间或降级建议 |

日志必须脱敏，禁止记录完整 API Key、用户隐私、完整素材原文和视频下载私密链接。

## 后端验收标准

| 维度 | 验收标准 |
|------|----------|
| **接口稳定** | 参数、响应、错误码和字段含义明确 |
| **任务可追踪** | 长任务有 task_id、status、progress、error 和结果字段 |
| **失败可恢复** | 模型失败、网络失败、任务失败有重试或可解释提示 |
| **日志可定位** | 能通过 request_id 或 task_id 定位问题 |
| **密钥安全** | API Key 只走环境变量，不进代码、不进日志、不返回前端 |
| **文件安全** | 上传文件限制大小、类型和解析路径 |
| **成本可控** | 记录模型、token、耗时和失败率，避免无界调用 |
