## 前端实现原则

1. **最小正确改动**：能局部组件解决，不动全局架构。
2. **直播操作稳定**：提词器操作不能依赖复杂鼠标点击路径。
3. **状态可见**：AI、语音、文件、视频任务都必须明确显示状态。
4. **降级可用**：语音识别、docx 解压、全屏等能力失败时给清晰提示。
5. **构建必过**：每次功能修改后优先保证 TypeScript 和 Vite 构建通过。

## 前端开发方法论

### 1. 先确认交互状态

开发前先把默认、输入中、生成中、成功、失败、权限拒绝、浏览器不支持等状态列清楚，避免只实现理想路径。

### 2. 再拆组件边界

页面级组件负责数据组织和流程控制，业务组件负责具体模块，基础组件负责按钮、卡片、标签、输入和状态展示。

### 3. 优先打通核心链路

先保证素材输入、AI 生成、内容编辑、提词播放和任务状态可用，再补充动效、偏好设置和增强交互。

### 4. 对 Web API 做降级

Fullscreen、SpeechRecognition、File、localStorage 等能力都要判断支持情况，并给用户可理解的替代路径或提示。

## 组件实现模板

当我输出前端实现方案时，默认包含以下结构：

1. **涉及页面**：列出要改的页面和路由。
2. **组件拆分**：页面组件、业务组件、基础组件的职责。
3. **状态设计**：核心响应式状态、计算状态、异步状态和错误状态。
4. **事件流**：用户操作如何触发状态变化和接口请求。
5. **接口依赖**：请求参数、响应字段、错误码、流式协议。
6. **降级策略**：浏览器不支持、权限拒绝、网络失败时如何处理。
7. **验证方式**：构建、手测路径、关键浏览器和边界输入。

## 接口联调清单

| 检查项 | 要求 |
|--------|------|
| **字段稳定** | 前端不猜字段，接口返回结构明确 |
| **错误可展示** | 错误码和错误文案能转成用户可理解提示 |
| **流式可中断** | Copilot 或生成流支持结束、失败和取消状态 |
| **任务可轮询** | 视频任务有 task_id、status、progress、error、file_url |
| **空数据可处理** | 空数组、空字符串、null、缺字段不导致页面崩溃 |
| **超时可恢复** | 网络慢或请求失败时可以重试或返回安全状态 |

## 前端验收标准

| 维度 | 验收标准 |
|------|----------|
| **构建质量** | TypeScript 无明显类型错误，Vite 构建通过 |
| **核心链路** | 首页入口、AI 生成、脚本编辑、提词播放、任务状态可完整操作 |
| **交互稳定** | 播放、暂停、快捷键、全屏、文件导入等操作不互相冲突 |
| **响应式** | 桌面、平板、手机关键流程可用 |
| **安全渲染** | AI 生成内容默认按文本渲染，不直接使用危险 HTML |
| **异常处理** | 权限拒绝、浏览器不支持、接口失败、文件损坏均有提示 |
| **可维护性** | 组件职责清晰，避免大段重复逻辑和无意义全局状态 |

---

## 降级与异常处理边界

| 场景 | 处理原则 |
|------|----------|
| **语音识别不可用** | 提示浏览器限制，保留手动播放和段落跳转 |
| **全屏失败** | 保留页面内大屏模式，不阻断提词功能 |
| **文件解析失败** | 显示失败原因，允许用户改为粘贴文本 |
| **localStorage 不可用** | 不保存偏好，但核心操作继续可用 |
| **流式接口中断** | 保留已生成内容，提示重试或重新生成 |
