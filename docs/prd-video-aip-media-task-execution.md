# PRD：视频 AIP 真实图片/视频任务执行

## 1. 产品判断

本需求应该做。视频 AIP 不能只停留在“生成提示词”，否则用户仍然需要手动复制提示词到外部工具，再把结果传回系统。正确方向是把每一步 AIP 链路接入真实图片/视频模型任务，让系统能够保存项目、逐步执行、轮询任务状态、回写产物，并最终形成可预览、可下载的视频结果。

本需求承接 `PRD：统一生成配置侧栏与视频 AIP 链路`，重点补齐“提示词步骤 -> 媒体任务 -> 任务状态 -> 产物回写”的执行闭环。

## 2. 业务目标

把现有视频 AIP 提示词链路升级为可执行的媒体任务流水线。

目标：

1. 用户创建视频 AIP 项目后，每个步骤都可以执行真实图片或视频任务。
2. 产品宣传大片链路支持主体清理、产品多视图、分镜图、最终视频生成。
3. 人物短剧链路支持角色四视图、文本剧本生成、剧情分镜图、最终短剧视频生成。
4. 每个步骤有明确状态、任务 ID、输入参数、输出素材、错误信息。
5. 用户可以查看执行进度、预览阶段产物、失败后重试。
6. 系统保留提示词、模型、参数和结果快照，方便复用与排错。

## 3. 用户流程

1. 用户在 IP 全案工作台选择视频 AIP 链路类型。
2. 用户上传产品图、人物图或其他参考素材。
3. 用户填写视频目标、卖点、剧情、平台、比例、时长、风格等配置。
4. 系统生成 AIP 项目和步骤计划。
5. 用户点击“执行下一步”或“执行全部”。
6. 系统调用对应图片/视频模型任务。
7. 页面显示步骤状态：待执行、执行中、成功、失败。
8. 步骤成功后展示输出图片、视频、素材 URL 或提示词结果。
9. 后续步骤自动引用前一步产物作为输入。
10. 最终视频生成完成后，用户可以预览、下载、复用到发布流程。

## 4. 链路范围

### 4.1 产品宣传大片链路

| 步骤 | 任务类型 | 输入 | 输出 |
|---|---|---|---|
| 主体清理 | 图片任务 | 产品原图、主体清理提示词 | 主体图、透明背景图或干净背景图 |
| 三/四视图 | 图片任务 | 主体图、产品信息、多视图提示词 | 正面、侧面、背面、细节视图 |
| 九/三十六宫格分镜 | 图片任务 | 多视图图、卖点、风格、分镜提示词 | 分镜图、镜头说明、镜头顺序 |
| 最终视频生成 | 视频任务 | 主体图、多视图、分镜、用户要求、最终动态提示词 | 视频 URL、任务结果 |

### 4.2 人物短剧链路

| 步骤 | 任务类型 | 输入 | 输出 |
|---|---|---|---|
| 多角色四视图 | 图片任务 | 人物图、角色设定、四视图提示词 | 每个角色的四视图 |
| 剧情脚本 | 文本任务 | 人物关系、冲突、反转、产品或观点 | 剧情脚本、台词、镜头节奏 |
| 图片分镜图 | 图片任务 | 剧情脚本、角色四视图、分镜提示词 | 分镜图、镜头说明、人物动作表情 |
| 最终视频生成 | 视频任务 | 剧本、角色四视图、分镜图、最终动态提示词 | 短剧视频 URL、任务结果 |

## 5. 功能需求

### 5.1 AIP 项目保存

系统需要保存视频 AIP 项目，支持恢复、查看和继续执行。

项目字段建议：项目 ID、用户 ID、链路类型、项目标题、输入素材、用户配置、当前状态、当前步骤、最终视频 URL、创建时间、更新时间。

项目状态：planned、running、succeeded、failed、cancelled。

### 5.2 步骤任务保存

每个 AIP 步骤都需要保存为独立任务。

步骤字段建议：步骤 ID、项目 ID、步骤 key、步骤名称、步骤顺序、任务类型、模型类型、模型 ID、输入 JSON、提示词、输出 JSON、任务 ID、状态、错误码、错误信息、开始时间、完成时间。

步骤状态：pending、running、succeeded、failed、skipped。

### 5.3 真实模型任务执行

系统需要把步骤映射到真实任务执行器。

| 步骤类型 | 执行器 |
|---|---|
| subject_cleanup | 图片生成或图片编辑模型 |
| multi_view | 图片生成模型 |
| character_views | 图片生成模型 |
| storyboard_grid | 图片生成模型 |
| image_storyboard | 图片生成模型 |
| final_video_prompt | 视频生成模型 |
| final_video | 视频生成模型 |

执行器需要统一返回任务 ID、状态、输出素材 URL、原始响应和错误信息。

### 5.4 状态轮询与产物回写

系统需要支持媒体任务轮询。

要求：

1. 提交任务后立即记录外部任务 ID。
2. 前端可轮询项目详情或步骤详情。
3. 后端可查询外部模型任务状态。
4. 任务成功后把图片、视频、缩略图、下载地址写回步骤输出。
5. 任务失败后保存错误码、错误信息、原始响应摘要。
6. 重试时保留历史失败记录，不覆盖关键排错信息。

### 5.5 前后步骤依赖

后续步骤应优先使用前置步骤产物，而不是重新依赖用户原图。

依赖规则：

| 后续步骤 | 依赖来源 |
|---|---|
| 多视图 | 主体清理输出图 |
| 产品分镜 | 多视图输出图、产品卖点 |
| 产品最终视频 | 分镜图、主体图、多视图、最终提示词 |
| 角色分镜 | 角色四视图、剧情脚本 |
| 人物最终视频 | 角色四视图、分镜图、短剧提示词 |

### 5.6 前端交互

视频 AIP 项目页需要展示步骤化执行体验。

页面能力：

| 区域 | 功能 |
|---|---|
| 项目概览 | 链路类型、项目状态、当前步骤、最终视频 |
| 步骤列表 | 步骤名称、状态、模型、耗时、错误提示 |
| 步骤详情 | 输入素材、提示词、输出图片/视频、原始参数摘要 |
| 操作按钮 | 执行下一步、执行全部、重试、跳过、查看产物 |
| 结果区 | 图片预览、视频预览、下载、复制提示词 |

### 5.7 失败与重试

失败时必须给用户明确原因。

常见失败类型：素材不符合要求、模型配置缺失、API Key 无效、模型任务超时、图片上传失败、视频生成失败、外部服务限流、输出结果为空。

重试规则：用户可以重试失败步骤；重试默认复用上次输入和提示词；用户修改素材或参数后，应生成新的步骤输入快照。

## 6. 后端接口需求

建议接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/video-aip/projects` | 创建 AIP 项目 |
| GET | `/api/video-aip/projects` | 获取项目列表 |
| GET | `/api/video-aip/projects/{id}` | 获取项目详情和步骤 |
| POST | `/api/video-aip/projects/{id}/steps/{step_id}/run` | 执行单个步骤 |
| POST | `/api/video-aip/projects/{id}/run-next` | 执行下一步 |
| POST | `/api/video-aip/projects/{id}/run-all` | 执行全部可执行步骤 |
| POST | `/api/video-aip/projects/{id}/steps/{step_id}/retry` | 重试失败步骤 |
| POST | `/api/video-aip/projects/{id}/steps/{step_id}/skip` | 跳过步骤 |
| GET | `/api/video-aip/tasks/{task_id}` | 查询外部媒体任务状态 |

## 7. 数据表需求

### 7.1 video_aip_projects

字段：id、user_id、title、workflow_type、status、source_assets_json、config_json、current_step_key、final_video_url、final_output_json、created_at、updated_at。

### 7.2 video_aip_step_tasks

字段：id、project_id、step_key、step_name、step_order、task_type、model_type、model_id、prompt、input_json、output_json、external_task_id、status、error_code、error_message、started_at、finished_at、created_at、updated_at。

### 7.3 media_assets

如已有统一媒体素材表，优先复用；否则建议新增或扩展。

字段：id、user_id、project_id、step_task_id、asset_type、url、thumbnail_url、mime_type、width、height、duration、source、metadata_json、created_at。

## 8. 模型与配置需求

需要复用后台大模型配置能力。

模型类型：image、video、text、multimodal。

配置字段：供应商、模型 ID、API Key、Base URL、默认参数、超时、重试次数、是否启用、是否默认。

执行任务时必须保存模型配置快照，避免后续后台改模型后无法追溯历史生成结果。

## 9. MVP 范围

第一阶段先打通可执行闭环。

| 优先级 | 内容 |
|---|---|
| P0 | AIP 项目和步骤任务持久化 |
| P0 | 单步执行、状态更新、失败记录、重试 |
| P0 | 主体清理、四视图、分镜、最终视频步骤映射到媒体任务 |
| P0 | 前端展示步骤状态和输出产物 |
| P0 | 最终视频预览和下载 |

| P1 | 多模型选择和参数快照 |
| P1 | 任务轮询与后台自动回写 |

## 9.1 当前实现状态

已实现首版单步真实任务闭环：

1. 后端新增 `video_engine.runtime.submit_media_task(...)`，统一提交 Pixelle 图片/视频媒体任务。
2. 后端新增 `POST /api/video/generate-media`，可直接提交通用图片/视频生成任务。
3. 后端新增 `GET /api/video/tasks/{task_id}/media-file`，用于读取本地生成的图片或视频文件。
4. 后端新增 `POST /api/copilot/video-aip/projects/{project_id}/steps/{step_id}/run`，把 AIP 步骤提交为真实媒体任务。
5. AIP 计划步骤增加 `task_type`、`artifact_type`、`default_media_type`、默认尺寸等元数据。
6. 产品链路中的主体清理、四视图、九宫格分镜、最终视频均映射为真实图片/视频任务。
7. 人物短剧链路中的角色四视图、图片分镜、最终短剧视频映射为真实图片/视频任务；剧情脚本步骤已接入文本模型生成结构化剧本。
8. 后续步骤会把已完成的上游产物 URL 或文本剧本摘要附加到任务提示词中，作为一致性参考。
9. 上传素材会同时以 `media_notes` 文本和 `source_assets` 结构化引用保存到 AIP 项目，首步执行时注入原始素材路径/说明。
10. 前端 AIP 项目步骤增加“执行生成”按钮，提交任务后轮询 `/api/video/tasks/{task_id}`。
11. 任务成功后，前端将任务 ID、进度、产物 URL/文件地址、时长、文件大小回写到步骤 `output_json`，并在步骤卡片中预览图片或视频。
12. 后端媒体任务完成后会通过任务完成回调自动回写步骤状态和产物，避免页面关闭后丢失结果。
13. AIP 媒体步骤提交时创建统一 `GenerationTask` 和 `GenerationRecord`，成功回调后把产物沉淀为 `UnifiedAsset` 并回写 `asset_id`。
14. AIP 项目已增加 `user_id`，列表、详情、执行、重试和手动更新按当前登录用户过滤。
15. 已新增 `POST /api/copilot/video-aip/projects/{project_id}/run-next`，支持从当前进度执行下一步。
16. 已新增 `POST /api/copilot/video-aip/projects/{project_id}/run-all`，支持后台按步骤顺序执行全部可执行任务。
17. 已新增 `POST /api/copilot/video-aip/projects/{project_id}/steps/{step_id}/retry`，支持失败步骤重试并保留上一次任务摘要到 `retry_history`。
18. 前端项目卡片增加“执行下一步”和“执行全部”，步骤卡片增加“重试”。
19. 已新增 `POST /api/copilot/video-aip/projects/from-short-video/{short_video_project_id}`，支持从短视频工作流项目创建 AIP 执行项目。
20. 已新增 `POST /api/copilot/video-aip/projects/from-storyboard/{storyboard_id}`，支持从平台分镜记录创建 AIP 执行项目，并保留分镜素材引用。
21. Copilot 短视频工作流增加“转入视频 AIP”入口；平台内容工作台分镜记录增加“转入视频 AIP”入口。
22. `video_aip_projects` 已增加 `source_type/source_ref_id` 来源反链，项目列表支持按来源类型和来源 ID 筛选。
23. AIP 项目详情和列表会返回 `source` 来源摘要，包含来源标题、类型标签、状态/场景和前端锚点，方便回跳原工作流或分镜。

## 9.2 当前保留缺口

1. `/api/video/tasks/{task_id}` 仍优先依赖运行时内存任务注册表，服务重启或多 worker 场景需要持久化兜底。
2. 后台 `video_model_config_id` 已保存和快照，但尚未完整映射为 Pixelle workflow 或供应商级执行参数。
3. AIP 资产已进入统一资产库，但尚未和具体 `IpProject`、平台内容发布链路形成强业务关联。
4. 短视频工作流项目、平台分镜记录已能转入 Video AIP，并保留来源反链和来源摘要；后续仍需补真实路由回跳和批量版本选择。
5. 外部长任务还缺独立补偿轮询和跨进程恢复机制。

## 10. 验收标准

1. 用户可以创建产品宣传大片或人物短剧 AIP 项目。
2. 系统会为项目生成可执行步骤列表。
3. 用户可以执行主体清理、四视图、分镜图、最终视频步骤。
4. 每个步骤都有 pending、running、succeeded、failed 状态。
5. 每个步骤成功后能看到对应图片或视频产物。
6. 后续步骤能引用前一步输出素材。
7. 最终视频生成成功后可以预览和下载。
8. 步骤失败时能看到明确错误原因。
9. 用户可以重试失败步骤。
10. 系统保存外部任务 ID、模型配置、输入参数、输出结果和错误信息。
11. 页面刷新后项目和步骤状态不丢失。
12. 未接入真实模型时，页面不能暗示“已经自动出图/出视频”。

## 11. 关键风险

| 风险 | 应对 |
|---|---|
| 外部模型输出不稳定 | 保存多个候选结果，允许人工选择继续下一步 |
| 产品包装或人物一致性差 | 强化多视图和参考图约束，失败时允许重试和替换素材 |
| 视频任务耗时长 | 前端使用轮询和明确状态，不阻塞页面 |
| API Key 或模型配置错误 | 执行前校验模型配置，失败时给出可操作错误 |
| 任务链路中断 | 步骤级持久化，支持从失败步骤继续执行 |
| 费用不可控 | 后续增加执行前预估和消耗记录 |
