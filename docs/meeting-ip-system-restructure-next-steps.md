# 会议纪要：IP 全案系统重构下一步工作会

## 1. 会议背景

本次会议基于 `PRD：IP 全案打造系统平台化重构` 和 `PRD：公众号排版与草稿发布` 召开，目标是把已经确认的产品方向转为第一阶段可执行工作。

已确认的产品方向：

1. 系统从工具集合升级为 IP 内容生产与发布闭环平台。
2. 核心结构采用 `IP 项目 -> 内容选题 -> 平台内容 -> 资产/任务/发布记录`。
3. 第一阶段优先做公众号完整闭环。
4. 统一提示词模板中心、模型池、素材中心、资产库、任务中心作为平台底座。
5. 小红书、视频号/抖音、短大片、剧本短视频先预留架构和配置口，不在第一阶段铺开完整页面。
6. 提词器不重做，只作为独立工具承接口播稿。

## 2. 参会角色

| 角色 | 会议职责 |
|---|---|
| 产品经理 | 收敛范围、定义阶段目标、确认优先级和验收标准 |
| UI/UX 设计师 | 设计信息架构、内容工作台、公众号编辑器、任务状态和资产库体验 |
| 前端开发 | 评估页面拆分、状态流、富文本编辑器和图片插入体验 |
| 后端开发 | 评估数据模型、接口、任务中心、提示词中心、模型池和微信链路 |
| 测试工程师 | 定义 E2E 验收、异常路径和上线门禁 |
| 合规顾问 | 定义内容合规检查、发布前风险提示和高风险阻断 |
| 安全专家 | 定义密钥、权限、XSS、SSRF、提示词注入和越权防护 |
| 内容运营/提示词工程 | 负责公众号模板种子、内容结构和模板效果复盘 |

## 3. 总体会议结论

第一阶段不追求所有板块同时上线，而是用公众号完整闭环验证平台底座。阶段目标是让用户可以完成：

`创建 IP 项目和内容选题 -> 链接/粘贴/主题输入 -> 选择公众号提示词模板 -> 生成结构化公众号文章 -> 类公众号富文本编辑 -> 自动封面/正文插图 -> 选择公众号账号 -> 发送到公众号草稿箱 -> 查看任务和发送记录 -> 沉淀到资产库`

第一阶段成功标准不是页面数量多，而是闭环稳定、失败可解释、数据可追溯、权限和密钥安全。

## 4. 范围收敛

### 4.1 第一阶段必须做

| 模块 | 必做内容 |
|---|---|
| 项目空间 | IP 项目、内容选题、平台内容归属 |
| 素材中心 | 链接、粘贴原文、主题输入 |
| 提示词模板中心 | 公众号模板、平台/场景/步骤/版本、启停、默认模板 |
| 模型池 | 文本和图片模型可用，按平台/场景/步骤解析默认模型 |
| 内容生成 | 结构化生成标题、摘要、正文、封面提示词、配图建议 |
| 公众号编辑器 | 类公众号富文本编辑、手机预览、HTML 输出、Markdown 快照 |
| 图片能力 | 自动封面、自动分析插图位、当前位置生成图片并插入 |
| 公众号账号 | 管理员配置多个公众号、启停、默认账号、测试连接 |
| 草稿发送 | 上传封面和正文图、调用 `draft/add`、保存发送记录 |
| 资产库 | 保存文章、封面、插图、发送记录、生成记录 |
| 任务中心 | 内容生成、图片生成、草稿发送状态和失败重试 |
| 权限安全 | 管理员/普通用户区分，普通用户只能使用授权账号 |
| 埋点 | 生成、图片、发送、失败等基础事件 |

### 4.2 第一阶段明确不做

1. 公众号自动群发。
2. 小红书自动发布。
3. 抖音/视频号自动发布。
4. 短大片三类完整上线。
5. 剧本短视频完整视频生成闭环。
6. 复杂团队协作、评论审批、多级组织权限。
7. 复杂数据看板。
8. 完全自由设计器和复杂个人排版模板市场。

## 8. 测试、合规、安全行动项

### 8.1 P0 上线门禁

| 门禁项 | 要求 |
|---|---|
| E2E 主链路 | 链接、粘贴、主题三种输入均可生成并发送草稿 |
| 微信真实测试 | 至少一个真实公众号账号完成 `draft/add` |
| 图片上传 | 封面和正文图片均上传微信并替换成功 |
| 密钥安全 | AppSecret 和模型 API Key 加密、脱敏、前端不可见 |
| 权限边界 | 普通用户不可管理公众号账号，不可使用未授权/停用账号 |
| HTML 安全 | XSS 清洗、危险标签和事件属性移除 |
| SSRF 防护 | 外链图片和链接解析禁止内网、localhost、file、云元数据地址 |
| 提示词注入 | 不泄露系统提示词，不破坏 JSON 输出，不泄露密钥 |
| 内容合规 | 高风险内容发送草稿前阻断或强提醒 |
| 失败可解释 | 微信错误码、图片失败、AI 失败必须显示可理解原因 |

## 10. 第一阶段最小上线标准

1. 用户可以创建 IP 项目和内容选题。
2. 用户可以通过链接、粘贴原文、主题三种方式生成公众号文章。
3. 生成结果必须结构化，包含标题、摘要、正文、封面提示词、配图建议。
4. AI 原始返回、模板版本、模型参数必须保存。
5. 用户可以进入类公众号富文本编辑器编辑文章。
6. 用户可以预览接近公众号移动端的阅读效果。
7. 用户可以生成或上传封面图。
8. 系统可以自动建议正文插图位置，并支持当前位置生成图片插入。
9. 管理员可以配置多个公众号账号、启停账号、测试连接。
10. 普通用户只能选择启用且授权的公众号账号。
11. 发送前完成标题、摘要、封面、正文图片、HTML、账号权限、合规检查。
12. 系统可以上传封面图和正文图到微信。
13. 系统可以调用微信公众号草稿接口创建草稿。
14. 成功和失败均保存发送记录、任务记录和错误原因。
15. AppSecret、access_token、模型 API Key 不在前端、日志和普通响应中明文出现。
16. XSS、SSRF、IDOR、提示词注入基础测试通过。
17. 高风险内容在发送草稿前阻断或强提醒。

## 11. 会议决议

1. 第一阶段不再继续扩展新需求，先围绕公众号闭环进入开发拆解。
2. 后端优先完成数据模型、迁移方案、任务中心和公众号账号权限改造。
3. 前端优先完成内容工作台、公众号富文本编辑器、草稿发送弹窗和任务状态设计。
4. 产品和提示词工程优先输出公众号模板种子、结构化 JSON schema 和发布前检查规则。
5. 测试、合规、安全从第一天介入，不等开发完成后再补测试。
6. 小红书、抖音/视频号、短大片、剧本短视频保留架构位置和后台配置口，待公众号闭环稳定后复用底座扩展。
