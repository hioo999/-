# 开发计划：视频 AIP 任务化流水线

## 目标

把现有“可复制的视频 AIP 提示词链路”升级为“可保存、可恢复、可逐步执行、可回写阶段产物的 AIP 项目”。

## 本阶段交付

| 模块 | 交付 |
|---|---|
| 后端数据 | `video_aip_projects` 和 `video_aip_step_tasks` |
| 后端接口 | 创建项目、项目列表、项目详情、步骤状态更新、单步执行、执行下一步、执行全部、重试 |
| 前端工作台 | 视频 AIP 板块支持生成链路、保存项目、执行/轮询/预览产物 |
| 步骤状态 | 每一步支持 pending、running、succeeded、failed，并保存任务 ID、错误和输出 JSON |
| 真实任务 | 产品大片与人物短剧的图片/视频步骤已桥接 Pixelle `submit_media_task` |
| 素材桥接 | 上传素材以 `source_assets` 强引用进入 AIP 项目，并注入首步执行 prompt |
| 文本桥接 | 剧本短视频的 `drama_script` 文本步骤调用文本模型生成结构化剧本 |
| 资产沉淀 | AIP 媒体步骤提交时创建统一 `GenerationTask`，成功回调后沉淀 `UnifiedAsset` |
| 入口桥接 | 短视频工作流项目、平台分镜记录均可一键创建 Video AIP 项目 |
| 来源反链 | AIP 项目保留 `source_type/source_ref_id`，支持按来源筛选 |
| 来源摘要 | AIP 项目响应返回 `source` 摘要，用于展示来源标题、类型、状态和回跳锚点 |

## 项目状态

| 状态 | 含义 |
|---|---|
| planned | 已生成计划，尚未执行 |
| running | 至少一个步骤正在执行 |
| succeeded | 所有步骤完成 |
| failed | 某一步失败 |

## 步骤状态

| 状态 | 含义 |
|---|---|
| pending | 待执行 |
| running | 执行中 |
| succeeded | 已完成 |
| failed | 执行失败 |

## 当前完成度

1. 产品宣传大片链路已覆盖主体清理、三/四视图、九/三十六宫格分镜、最终视频四步。
2. 人物短剧链路已覆盖多角色四视图、剧情脚本、图片分镜、最终短剧视频四步。
3. 媒体步骤已走真实图片/视频任务提交，并把任务 ID、状态、产物 URL、文件地址、尺寸和时长写回步骤输出。
4. 执行下一步和执行全部会按步骤顺序推进；文本步骤生成成功后，后续媒体步骤会引用该文本产物。
5. 上传素材不再只保存为 `media_notes` 文本，也会保存结构化 `source_assets`，用于后续一致性参考。
6. AIP 项目已按登录用户隔离，列表、详情、执行、重试和手动更新均只访问当前用户项目。
7. Copilot 短视频工作流可先保存项目再转入 Video AIP；平台内容工作台的分镜记录可直接转入 Video AIP。
8. 从短视频工作流或分镜创建的 AIP 项目会记录来源反链，并可通过列表接口按来源筛选。
9. AIP 项目列表和详情都会返回来源摘要，前端项目卡片展示可读来源标题和场景。

## 后续建议

1. 将 AIP 产物与业务 `IpProject`、平台内容、发布工作台建立显式关联，而不是只写入统一资产库。
2. 把 RunningHub/ComfyUI 外部任务 ID 持久化，增加服务重启后的补偿轮询。
3. 让后台视频模型配置真正映射到 Pixelle workflow 或供应商执行参数，而不是只进入提示词和快照。
4. 为短视频/分镜来源的 AIP 项目补真实路由回跳、来源详情侧栏和批量版本对比。
5. 增加候选版本、人工选片和成本统计。
