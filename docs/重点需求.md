# PRD：IP 全案打造系统平台化重构

## 1. 产品判断

本次重构应该做，而且不是新增单点功能，而是把现有能力从“工具集合”升级为“IP 内容生产与发布闭环平台”。系统核心应从单个生成页面转为以 `IP 项目 -> 内容选题 -> 平台内容 -> 资产/任务/发布记录` 为主线，统一承接公众号、小红书、视频号/抖音口播、短大片视频、剧本短视频和提词器。

已有能力不重复建设。现有提词器、公众号排版、视频 AIP、模型网关等能力继续保留，通过新架构逐步迁移入口、统一底座和数据归属。

第一阶段优先做公众号完整闭环，因为公众号具备明确的草稿箱接口，可以形成从素材输入、AI 二创、类公众号富文本排版、自动封面/插图、发送草稿箱到记录追踪的完整路径。

## 2. 总体目标

1. 建立以项目空间为核心的内容生产体系。
2. 建立统一提示词模板中心，所有平台和生成步骤的提示词都由后台配置。
3. 建立模型池，文本、图片、视频模型不写死，按任务能力选择。
4. 建立素材中心、资产库和任务中心，统一保存输入、生成结果、图片、视频、角色、分镜和发布记录。
5. 第一阶段打通公众号完整闭环。
6. 小红书、视频号/抖音、短大片、剧本短视频先纳入整体架构和后台配置，为后续阶段扩展预留接口和数据结构。

核心闭环：

`素材/主题输入 -> 选择后台提示词 -> 生成平台内容 -> 编辑/排版/配图/封面 -> 发布或进入下一步工具 -> 保存项目资产`

## 3. 核心决策

| 编号 | 决策项 | 结论 |
|---|---|---|
| 1 | 项目空间 | 采用 `IP 项目 + 内容选题` 两层结构 |
| 2 | 第一阶段 | 做公众号完整闭环 |
| 3 | 提示词 | 做全平台统一提示词模板中心 |
| 4 | 公众号账号 | 管理员配置多个公众号，普通用户可选择授权账号；后续支持用户绑定 |
| 5 | 小红书发布 | 第一版不承诺自动发布，只做内容、图片、复制和下载 |
| 6 | 视频号/抖音发布 | 第一版不自动发布，但后台预留发布配置口 |
| 7 | 模型 | 做模型池，文本、图片、视频模型均可配置 |
| 8 | 多步骤任务流 | 短大片和剧本短视频底层共用任务流，页面分开 |
| 9 | 人物角色库 | 第一版基础角色库，后期扩展人物关系图谱；角色数量可限制 |
| 10 | 重构方式 | 新建统一架构，已有能力逐步接入 |

## 4. 用户与场景

| 用户类型 | 核心任务 |
|---|---|
| 内容创作者 | 从主题、链接、文章或素材快速生成多平台内容 |
| 企业 IP 运营者 | 围绕一个 IP 项目持续产出公众号、小红书、短视频内容 |
| 运营助理 | 将二创内容排版、配图、发送公众号草稿箱 |
| 短视频团队 | 生成口播文案、封面、录屏脚本、分镜和视频素材 |
| 编导/内容策划 | 管理人物角色、剧本、多集短剧和分镜资产 |
| 管理员 | 管理提示词、模型、公众号账号、任务日志和系统配置 |

## 6. 项目空间设计

系统采用两层项目结构：

`IP 项目 -> 内容选题`

示例：

`李老师知识 IP -> 如何选择专业 -> 公众号文章 / 小红书笔记 / 抖音口播 / 封面 / 配图 / 草稿记录`

### 6.1 IP 项目

| 字段 | 说明 |
|---|---|
| 项目名称 | 例如“李老师知识 IP” |
| IP 类型 | 个人 IP、企业 IP、产品 IP、宠物 IP、虚拟人 IP |
| 账号定位 | 专业方向、受众、风格、内容边界 |
| 默认平台 | 公众号、小红书、抖音、视频号等 |
| 默认人设 | 口吻、语气、禁用表达、常用结构 |
| 项目资产 | 素材、文案、图片、视频、角色、发布记录 |

### 6.2 内容选题

| 字段 | 说明 |
|---|---|
| 选题名称 | 当前内容主题 |
| 输入来源 | 链接、粘贴原文、主题、文件、图片、视频 |
| 目标平台 | 公众号、小红书、抖音、视频号等 |
| 生成内容 | 文章、笔记、口播稿、剧本、封面、分镜 |
| 状态 | 草稿、生成中、待编辑、待发布、已发送、已归档 |

## 7. 统一底座

### 7.1 素材中心

统一接收以下输入：

| 输入类型 | 说明 |
|---|---|
| 链接 | 文章、网页、商品页、公众号文章等 |
| 粘贴原文 | 用户复制的文章、资料、笔记、卖点 |
| 主题 | 一句话选题或需求描述 |
| 文件 | 文档、表格、PDF 等 |
| 图片 | 产品图、人物图、宠物图、参考图 |
| 视频 | 参考视频、产品视频、素材视频 |

素材解析结果统一保存为结构化内容，供不同平台提示词调用。

### 7.2 提示词模板中心

提示词模板按以下层级管理：

`平台 -> 场景 -> 步骤 -> 模板 -> 版本`

示例：

`公众号 -> 二创文章 -> 正文生成 -> 专业观点型模板 -> v1.0`

`短大片 -> 产品视频 -> 三视图生成 -> 电商产品三视图模板 -> v1.0`

模板能力：

| 能力 | 要求 |
|---|---|
| 平台区分 | 公众号、小红书、抖音、视频号、短大片、剧本短视频 |
| 场景区分 | 二创、原创、带货、口播、封面、配图、分镜、角色设定 |
| 步骤区分 | 内容生成、标题生成、图片提示词、视频提示词、分镜词等 |
| 版本管理 | 每次生成保存模板 ID、模板 Key、版本 |
| 启停管理 | 停用模板前端不可选，历史记录可追溯 |
| 默认模板 | 每个平台/场景/步骤可配置默认模板 |
| 排序权重 | 前端选择器按权重展示 |
| 输出结构 | 支持要求 AI 输出 JSON、Markdown、分镜表、提示词文本 |
| 权限 | 普通用户只看模板名称和说明，不看完整系统提示词 |

### 7.3 模型池

模型池支持文本、图片、视频三类模型，并承接现有模型网关 PRD。

| 模型类型 | 用途 |
|---|---|
| 文本模型 | 文章、笔记、口播、标题、标签、剧本、分镜词 |
| 图片模型 | 封面、正文插图、人物图、多视图、九宫格、分镜图 |
| 视频模型 | 短大片、剧本短视频、图生视频、文生视频 |

要求：

1. 管理员可配置全局默认文本、图片、视频模型。
2. 用户可配置个人默认模型。
3. 不同平台和步骤可绑定不同默认模型。
4. 每次生成保存模型 ID、网关、参数和模型快照。
5. 前端可允许用户选择模型，但后台可提供默认值和推荐值。

### 7.4 资产库

所有生成结果都进入资产库，按项目隔离。

| 资产类型 | 示例 |
|---|---|
| 原始素材 | 链接、粘贴文本、上传文件、图片、视频 |
| 生成文案 | 公众号文章、小红书笔记、口播稿、剧本 |
| 图片资产 | 封面、正文插图、人物图、多视图、九宫格、分镜图 |
| 视频资产 | 生成视频、预览视频 |
| 角色资产 | 人物设定、参考图、四视图、八视图 |
| 发布资产 | 公众号草稿记录、小红书导出记录、后续平台发布记录 |
| 生成记录 | 模板 ID、版本、模型、参数、原始 AI 返回内容 |

资产库要求：

1. 支持按项目、选题、平台、类型筛选。
2. 支持复用历史文案、图片、角色和分镜。
3. 支持资产标签。
4. 支持用户删除资产，但发布记录和生成日志保留。

### 7.5 任务中心

所有 AI 生成、图片生成、视频生成、发布动作和素材解析都进入任务中心。

任务类型：

| 类型 | 示例 |
|---|---|
| 素材解析任务 | 链接提取、文件解析、图片理解 |
| 内容生成任务 | 公众号文章、小红书笔记、口播稿、剧本 |
| 图片生成任务 | 封面、插图、分镜图、多视图 |
| 视频生成任务 | 短大片、剧本短视频 |
| 发布任务 | 发送公众号草稿箱 |

任务状态：

`待执行 -> 执行中 -> 成功 -> 失败 -> 已取消 -> 重试中`

要求：

1. 失败任务保存错误码、错误信息和原始响应摘要。
2. 支持失败重试。
3. 前端至少展示生成中、成功、失败。
4. 后台可查看任务日志。

## 8. 第一阶段：公众号完整闭环

### 8.1 输入方式

| 输入方式 | 说明 |
|---|---|
| 链接提取 | 提取原始内容，再通过后台提示词生成公众号二创内容 |
| 粘贴原文 | 用户复制原文，通过选定提示词生成二创内容 |
| 主题输入 | 用户输入主题，根据提示词生成公众号内容 |

### 8.2 公众号生成结构

公众号生成结果必须结构化，至少包含：

```json
{
  "title": "文章标题",
  "subtitle": "副标题",
  "author": "作者",
  "summary": "摘要",
  "cover_prompt": "封面图提示词",
  "cover_image_url": "",
  "content_html_or_delta": "类公众号富文本正文结构",
  "markdown_snapshot": "Markdown 快照，用于导出和兼容转换",
  "image_slots": [
    {
      "position": "after_paragraph_2",
      "purpose": "解释核心概念",
      "prompt": "配图提示词"
    }
  ],
  "tags": ["IP打造", "内容创作"],
  "compliance_risks": []
}
```

要求：

1. 后台提示词模板必须要求输出 JSON。
2. AI 返回格式错误时后端自动修复或重试。
3. 生成历史保存原始 AI 返回内容，便于排查。
4. 标题、摘要、正文、封面提示词、配图建议必须拆出。

### 8.3 公众号排版编辑器

第一阶段采用类似公众号富文本编辑器，而不是只做 Markdown 编辑器。

核心能力：

| 能力 | 要求 |
|---|---|
| 富文本编辑 | 标题、正文、加粗、引用、列表、分割线、图片、链接 |
| 公众号样式组件 | 金句卡、重点段落、引用卡片、关注引导、推荐阅读 |
| 手机预览 | 接近公众号移动端阅读效果 |
| HTML 预览/导出 | 生成公众号兼容 HTML，支持复制 HTML |
| Markdown 快照 | 兼容已有 Markdown 生成和导出 |
| 自动保存 | 编辑过程中保存草稿 |
| 手动上传图片 | 用户可上传封面和正文图 |
| AI 生成图片 | 支持当前位置一键生成图片并插入 |

### 8.4 自动封面与正文插图

第一阶段支持：

1. 根据标题、摘要、正文自动生成封面提示词。
2. 调用模型池中的图片模型生成封面图。
3. 自动分析文章结构，建议插图位置。
4. 用户可在正文当前位置一键生成图片并插入。
5. 用户可生成金句卡、一图总结、方法论卡、结尾引导卡。
6. 图片生成失败时允许继续编辑；发送草稿时封面图必须存在。

### 8.5 公众号账号与草稿箱

第一阶段账号策略：管理员配置多个公众号账号，普通用户可选择管理员授权的账号；第一版不做复杂账号分组和权限，只做启用/停用。

要求：

| 能力 | 要求 |
|---|---|
| 多公众号账号 | 第一版支持配置多个公众号 |
| 默认账号 | 管理员可设置默认账号 |
| AppSecret | 加密保存，前端不明文返回 |
| 测试连接 | 校验 access_token、接口权限、图片上传能力 |
| 用户选择 | 普通用户可选择启用且授权的公众号 |
| 发送记录 | 按公众号账号保存草稿发送记录 |
| 自动群发 | 第一版不做 |

发送流程：

1. 用户在公众号排版页确认标题、作者、摘要、封面、正文。
2. 用户选择公众号账号。
3. 系统获取 access_token。
4. 系统上传封面图，获得 `thumb_media_id`。
5. 系统上传正文图片并替换为微信图片 URL。
6. 系统生成公众号兼容 HTML。
7. 系统调用 `draft/add` 创建草稿。
8. 系统保存草稿发送记录。
9. 用户到公众号后台检查后手动发布。

## 9. 第二阶段：小红书创作

第一版小红书不承诺自动发布，只做内容和图片生成闭环。

### 9.1 输入方式

1. 链接提取原始内容，通过后台提示词生成小红书二创内容。
2. 粘贴原文，通过选定提示词生成小红书内容。
3. 输入主题，根据提示词生成小红书内容。

### 9.2 输出内容

| 输出 | 要求 |
|---|---|
| 标题 | 多个小红书标题备选 |
| 正文笔记 | 小红书语气、结构、互动引导 |
| 标签话题 | 自动生成话题标签 |
| 首图封面 | 单独生成首图封面 |
| 多张配图 | 默认生成 3 张，可选 1/3/6/9 |
| 图片模型 | 可从模型池选择 ChatImage2 或其他图片模型 |
| 导出 | 支持复制文案、下载图片 |

### 9.3 后期预留

1. 后台预留小红书发布配置口。
2. 后期支持自动发布、账号授权、发布记录和失败重试。
3. 后期支持图文卡片风格、封面模板、批量笔记。

## 10. 第三阶段：视频号/抖音口播

第一版不做自动发布，但后台预留抖音/视频号发布配置口。

### 10.1 输入方式

1. 链接提取原文，生成二创口播文案。
2. 粘贴原文，生成二创口播文案。
3. 主题输入，生成口播文案。

### 10.2 输出内容

| 输出 | 要求 |
|---|---|
| 口播文案 | 适配抖音或视频号平台语气 |
| 标题 | 多个标题备选 |
| 描述 | 发布描述 |
| 标签 | 平台标签 |
| 录屏脚本 | 教程类内容生成录屏操作步骤和旁白 |
| 封面提示词 | 根据标题、人物、参考图生成 |
| 封面图 | 调用图片模型生成 |
| 提词器 | 一键发送到已有提词器 |

视频号和抖音共用一个“口播短视频”页面，通过平台参数区分。第一版先单平台生成，后期支持同一内容一键生成抖音版和视频号版。

## 11. 第四阶段：短大片工厂

短大片用于产品、宠物、人物 IP 图片到高级短视频的多步骤生成。

### 11.1 第一版范围

第一版建议先做产品短大片闭环，宠物和人物 IP 作为模板预留。

产品流程：

1. 用户上传产品图。
2. 根据提示词清除背景，生成主体图。
3. 根据提示词生成产品三视图。
4. 根据提示词生成九宫格动作/场景图。
5. 生成分镜图和分镜词。
6. 上传主体图、三视图、九宫格、分镜图、分镜词。
7. 选择视频模型、比例、时长。
8. 生成视频并保存到资产库。

### 11.2 通用要求

| 能力 | 要求 |
|---|---|
| 步骤提示词 | 每一步可选择不同提示词模板，也可使用默认模板 |
| 单步重试 | 某一步失败可单独重试 |
| 手动替换 | 每一步允许用户手动上传替换结果 |
| 资产保存 | 每一步结果必须保存到资产库 |
| 任务状态 | 通过任务中心展示状态 |
| 模型选择 | 每一步可绑定不同默认模型 |

## 12. 第五阶段：剧本短视频

剧本短视频用于多人物、多集剧情、分镜和视频生成。

### 12.1 主流程

1. 用户上传多个人物全身照。
2. 系统生成四视图、八视图等角色设定图。
3. 用户补充人物姓名、身份、性格、说话风格、口头禅。
4. 保存成人物角色。
5. 用户输入主题或剧情方向。
6. 用户选择已保存人物。
7. 系统生成单集或多集剧本。
8. 系统生成分镜表和分镜图。
9. 用户选择秒数、比例、视频模型。
10. 系统生成视频。

### 12.2 第一版限制

| 限制项 | 默认值 |
|---|---|
| 单个剧本项目角色数 | 最多 6 个 |
| 单次上传人物图 | 最多 6 张 |
| 单个角色参考图 | 最多 8 张 |
| 第一版多集剧本集数 | 最多 10 集 |
| 单集分镜数量 | 默认 8-12 个 |
| 单个视频时长 | 默认 15 秒、30 秒、60 秒 |

### 12.3 后期扩展

1. 人物关系图谱。
2. 角色跨项目复用。
3. 全局模板角色。
4. 多集连续剧项目管理。
5. 角色一致性评分和分镜连续性检查。

第一版角色库属于 IP 项目，管理员后期可设置全局模板角色。

| 小红书笔记 | 可选转成口播稿后进入提词器 |

## 14. 用户与权限

第一版至少区分三类角色：

| 角色 | 权限 |
|---|---|
| 管理员 | 管理提示词、模型、公众号账号、用户、任务日志 |
| 运营/编辑 | 创建项目、生成内容、排版、发送草稿 |
| 普通用户 | 使用授权功能，管理自己的项目内容 |

权限要求：

1. 第一版需要登录权限。
2. 提示词模板只有管理员能改。
3. 公众号账号第一版只有管理员能配置。
4. 普通用户可以发送公众号草稿，但只能使用启用且授权的公众号账号。
5. AppSecret、API Key 不允许前端明文展示。

## 20. 验收标准

### 20.1 平台重构验收

1. 用户可以创建 IP 项目和内容选题。
2. 用户可以在内容选题下选择目标平台和输入方式。
3. 后台可以按平台、场景、步骤、版本管理提示词模板。
4. 普通用户无法查看完整系统提示词正文。
5. 模型池可以区分文本、图片、视频模型，并有默认模型策略。
6. 每次生成都保存模板 ID、模板版本、模型 ID、模型参数和原始 AI 返回内容。
7. 所有生成结果进入资产库。
8. 所有 AI 生成、图片生成、草稿发送进入任务中心。
9. 用户可以从多平台工作台查看最近平台内容、任务和资产保留策略。
10. 删除平台内容时只从工作台隐藏，生成记录、任务和发布审计链路必须保留。
11. 用户可以生成、编辑和复制导出小红书图文内容。
12. 用户可以生成、编辑和导入提词器的抖音/视频号口播稿。
13. 用户可以为小红书/口播内容上传、绑定或生成图片资产。
14. 用户可以保存小红书/抖音/视频号发布配置预留项，敏感凭据不得明文返回。
15. 用户可以在项目内维护人物角色和分镜记录，作为剧本短视频后续闭环的基础资产。

### 20.2 公众号第一阶段验收

1. 用户可以通过链接、粘贴原文、主题三种方式生成公众号内容。
2. 公众号生成结果拆出标题、摘要、正文、封面提示词和配图建议。
3. AI 返回 JSON 格式错误时，系统可以自动修复或重试。
4. 用户可以进入类似公众号富文本编辑器继续编辑内容。
5. 用户可以预览接近公众号阅读效果的手机端页面。
6. 系统可以自动分析文章结构并建议插图位置。
7. 用户可以在正文当前位置一键生成图片并插入。
8. 用户可以生成封面图，也可以手动上传封面图。
9. 管理员可以配置多个公众号账号并启用/停用。
10. 普通用户可以选择启用且授权的公众号账号。
11. AppSecret 加密保存，前端不明文返回。
12. 系统可以测试公众号连接。
13. 系统可以上传封面和正文图片到微信。
14. 系统可以调用草稿接口创建公众号草稿。
15. 草稿发送记录按公众号账号保存。
16. 发送失败时展示可理解错误原因。

## 21. 关键风险

| 风险 | 应对 |
|---|---|
| 一次重构范围过大 | 分阶段实施，第一阶段只要求公众号完整闭环和必要底座 |
| 提示词模板过于混乱 | 强制平台、场景、步骤、版本结构，前端不暴露完整提示词 |
| AI 返回结构不稳定 | 要求 JSON 输出，失败时自动修复或重试，保存原始返回 |
| 富文本编辑器复杂度高 | 第一版优先支持公众号核心编辑和组件，不做完全自由设计器 |
| 微信接口权限问题 | 提供测试连接，提示 IP 白名单、账号类型、接口权限错误 |
| 图片上传和替换失败 | 发送前统一检查，定位到具体图片并支持重试 |
| 模型能力差异 | 模型池标注能力，步骤绑定默认模型，失败记录模型快照 |
| 旧功能迁移中断 | 采用新架构承接旧功能，提词器等成熟功能不推倒重做 |
