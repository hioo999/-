# PRD：大模型中转、模型发现与默认模型策略

## 1. 产品判断

本需求应该做。当前每个模型都要求用户手动选择或逐个配置，会导致配置成本高、模型列表滞后、不同生成能力之间选择混乱。正确方向是引入 OpenAI-compatible 大模型中转配置：用户只填写兼容接口的 `Base URL` 和 `API Key`，系统自动读取该 Key 下可用模型，并按文字、图片、视频能力提供推荐模型和默认模型。

本需求承接 `PRD：统一生成配置侧栏与视频 AIP 链路` 和 `PRD：视频 AIP 真实图片/视频任务执行`，重点补齐“模型配置 -> 模型发现 -> 能力标注 -> 推荐/默认选择 -> 生成调用”的统一底座。

## 2. 业务目标

1. 用户不再逐个手动录入模型 ID，而是通过中转 API Key 自动发现可用模型。
2. 系统把模型按能力归类为文字、图片、视频、多模态，减少错误选择。
3. 后台可以配置全局默认文字模型、图片模型、视频模型。
4. 用户可以在自己的 API Key 下设置个人默认文字模型、图片模型、视频模型。
5. 前端模型选择框旁展示推荐提示，帮助用户选择适合当前任务的模型。
6. 生成任务必须记录实际使用的模型、中转配置、参数和模型快照，便于追溯。

## 3. 用户流程

### 3.1 用户侧模型配置流程

1. 用户进入“模型配置”页面。
2. 用户选择“添加大模型中转”。
3. 用户填写配置名称、`Base URL`、`API Key`。
4. 用户点击“测试并拉取模型”。
5. 系统调用兼容接口的 `/models` 获取模型列表。
6. 系统展示该 Key 下所有可用模型，并尝试自动识别能力类型。
7. 用户确认模型能力类型，必要时手动修正文字、图片、视频、多模态标签。
8. 用户可设置个人默认文字模型、图片模型、视频模型。
9. 工作台生成内容时，模型下拉框只展示当前任务可用能力的模型。

### 3.2 后台管理员流程

1. 管理员进入后台“模型中转配置”。
2. 管理员配置系统级中转供应商或全局可用模型。
3. 管理员维护模型能力、推荐标签、排序权重、启停状态。
4. 管理员设置全局默认文字模型、图片模型、视频模型。
5. 当用户没有个人默认模型时，系统自动回退使用全局默认模型。

### 3.3 生成任务模型选择流程

1. 用户在工作台选择口播文案、封面图片、AIP 图片步骤或视频步骤。
2. 系统根据任务类型筛选模型能力。
3. 若用户设置了个人默认模型，优先自动选中个人默认。
4. 若没有个人默认，自动选中后台全局默认。
5. 若默认模型不可用，展示推荐模型并提示用户选择。
6. 生成任务提交时，后端记录模型配置快照。

## 4. 功能范围

### 4.1 OpenAI-compatible 中转接入

MVP 先支持兼容 OpenAI 接口形态的中转服务。

必填字段：

| 字段 | 说明 |
|---|---|
| 配置名称 | 用户自定义，如“我的中转账号” |
| Base URL | 兼容接口地址，如 `https://example.com/v1` |
| API Key | 用户自己的中转密钥，必须加密保存 |
| 启用状态 | 控制是否在生成时可用 |

系统行为：

| 行为 | 要求 |
|---|---|
| 测试连接 | 使用 API Key 调用 `/models` 或兼容模型列表接口 |
| 拉取模型 | 保存模型 ID、名称、原始响应摘要、更新时间 |
| 刷新模型 | 用户可手动刷新模型列表，后台也可定时刷新 |
| 失效处理 | Key 无效、余额不足、无权限、接口超时需要展示明确错误 |
| 安全保护 | 前端和日志不得暴露明文 API Key |

### 4.2 模型能力识别

系统需要为模型标注能力类型。

| 能力类型 | 用途 |
|---|---|
| text | 口播文案、标题、脚本、分镜文案、提示词生成 |
| image | 封面图、主体清理、人物四视图、产品多视图、分镜图 |
| video | 最终视频生成、图片转视频、文生视频 |
| multimodal | 图文理解、素材解析、图生文、参考图理解 |

能力识别优先级：

1. 后台管理员显式标注。
2. 用户在个人配置中手动修正。
3. 系统根据模型 ID 关键词做默认猜测。
4. 无法识别时标记为 unknown，不允许直接用于生成任务。

关键词猜测只能作为辅助，不得作为最终可信判断。示例：`gpt`、`claude` 可初步归为 text/multimodal；`flux`、`stable-diffusion` 可初步归为 image；`kling`、`runway`、`hailuo`、`veo` 可初步归为 video。

### 4.3 推荐模型提示

模型选择框旁需要展示推荐提示。

推荐信息包括：

| 信息 | 示例 |
|---|---|
| 推荐用途 | 推荐用于口播文案、推荐用于封面图、推荐用于视频 AIP |
| 推荐原因 | 速度快、质量高、成本低、适合中文、适合图生视频 |
| 风险提示 | 成本较高、生成较慢、可能不支持参考图 |
| 默认标记 | 全局默认、个人默认 |

推荐规则来源：

1. 后台管理员维护的推荐标签和排序。
2. 模型能力类型与当前任务类型匹配。
3. 用户个人默认模型优先展示。
4. 后续可接入历史成功率、耗时、成本等数据优化排序。

### 4.4 默认模型策略

系统需要支持全局默认和个人默认两级策略。

| 默认类型 | 配置人 | 生效范围 | 优先级 |
|---|---|---|---|
| 个人默认文字模型 | 用户 | 当前用户的文本生成任务 | 最高 |
| 个人默认图片模型 | 用户 | 当前用户的图片生成任务 | 最高 |
| 个人默认视频模型 | 用户 | 当前用户的视频生成任务 | 最高 |
| 全局默认文字模型 | 管理员 | 所有未设置个人默认的用户 | 次级 |
| 全局默认图片模型 | 管理员 | 所有未设置个人默认的用户 | 次级 |
| 全局默认视频模型 | 管理员 | 所有未设置个人默认的用户 | 次级 |

选择规则：

1. 任务明确需要 `text`、`image`、`video` 或 `multimodal` 能力。
2. 优先查找用户个人默认模型。
3. 个人默认不可用时查找全局默认模型。
4. 全局默认不可用时使用后台推荐排序第一的可用模型。
5. 仍无可用模型时阻止生成，并提示用户或管理员补充模型配置。

### 4.6 后端接口需求

建议接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/model-gateways` | 新增用户中转配置 |
| GET | `/api/model-gateways` | 获取用户中转配置列表 |
| PATCH | `/api/model-gateways/{id}` | 更新用户中转配置 |
| DELETE | `/api/model-gateways/{id}` | 删除或停用用户中转配置 |
| POST | `/api/model-gateways/{id}/test` | 测试连接和 Key 有效性 |
| POST | `/api/model-gateways/{id}/sync-models` | 拉取并保存模型列表 |
| GET | `/api/models` | 获取当前用户可用模型列表 |
| PATCH | `/api/models/{id}/capability` | 用户修正个人模型能力标签 |
| GET | `/api/model-defaults` | 获取个人默认和全局默认模型 |
| PUT | `/api/model-defaults` | 保存个人默认模型 |
| GET | `/api/admin/model-gateways` | 后台查看中转配置 |
| PATCH | `/api/admin/models/{id}` | 后台维护能力、推荐标签、启停状态 |
| PUT | `/api/admin/model-defaults` | 设置全局默认模型 |

生成接口需要统一接收或解析：

| 字段 | 说明 |
|---|---|
| capability | 当前任务需要的能力，如 text/image/video |
| model_id | 用户显式选择的模型 ID，可为空 |
| gateway_id | 使用的中转配置 ID，可为空 |
| default_resolution | 未显式选择模型时的默认解析结果 |
| model_snapshot | 后端最终写入的模型快照 |

### 4.7 数据表需求

#### model_gateways

字段建议：id、user_id、scope、name、provider_type、base_url、api_key_encrypted、status、last_test_status、last_test_message、last_synced_at、created_at、updated_at。

说明：`scope` 区分 user/admin/system；`provider_type` MVP 固定为 openai_compatible。

#### model_catalog

字段建议：id、gateway_id、user_id、model_id、display_name、capability、raw_capability_guess、status、raw_metadata_json、last_seen_at、created_at、updated_at。

说明：同一个中转配置下的 `model_id` 不应重复。

#### model_recommendations

字段建议：id、model_catalog_id、task_type、label、reason、risk_note、quality_score、speed_score、cost_score、sort_order、enabled、created_at、updated_at。

#### model_defaults

字段建议：id、scope、user_id、capability、model_catalog_id、gateway_id、created_at、updated_at。

说明：`scope=global` 时 `user_id` 为空；`scope=user` 时表示个人默认。

#### generation_model_snapshots

字段建议：id、generation_id、task_type、capability、gateway_id、base_url_hash、model_catalog_id、model_id、model_display_name、model_parameters_json、resolved_by、created_at。

说明：不得保存明文 API Key；`resolved_by` 记录 explicit、user_default、global_default、recommendation_fallback。

## 5. 安全与权限

1. API Key 必须加密存储，前端、日志、错误信息中不得出现明文 Key。
2. 用户只能查看、编辑、删除自己的中转配置。
3. 管理员可以停用模型或中转配置，但不应直接查看用户明文 Key。
4. 调用外部中转服务时需要设置超时、重试、错误摘要和请求 ID。
5. 模型原始响应需要脱敏后再入库，避免外部服务返回敏感信息。
6. 删除中转配置时，需要确认是否保留历史生成快照。

## 8. 当前实现边界

第一阶段只做 OpenAI-compatible 中转，不做所有厂商的私有协议适配。只要中转服务能够通过统一接口提供模型列表和生成接口，系统就可以接入。

对于图片和视频模型，不同中转服务的生成接口可能并不完全兼容 OpenAI 标准。MVP 需要先约定内部统一调用协议：模型发现可以统一走 `/models`，但具体 text/image/video 生成调用可以先适配现有后端执行器能力，无法确认协议的模型只允许出现在列表中，不允许直接生成。

## 9. 风险与注意事项

| 风险 | 处理方式 |
|---|---|
| `/models` 只能返回模型 ID，不能返回能力 | 允许后台和用户手动标注能力 |
| 中转商接口不完全兼容 | MVP 明确只保证模型发现和文本调用兼容，图片/视频按执行器能力逐步接入 |
| 用户 Key 失效或余额不足 | 生成前校验可用状态，失败时给出可操作提示 |
| 默认模型被停用 | 自动回退到推荐模型，并提示管理员修复默认配置 |
| 推荐模型误导用户 | 推荐提示必须展示推荐原因和风险提示 |
| API Key 泄露风险 | 加密存储、脱敏日志、前端不可回显、权限隔离 |

## 10. 验收标准

1. 用户可以新增一个 OpenAI-compatible 中转配置，并成功测试连接。
2. 用户点击“拉取模型”后，可以看到该 API Key 下的模型列表。
3. 模型列表中每个模型都有能力类型，无法识别的模型显示为 unknown。
4. 后台可以设置全局默认文字模型、图片模型、视频模型。
5. 用户可以设置个人默认文字模型、图片模型、视频模型。
6. 工作台进入口播生成时，默认选择文字模型，并显示推荐提示。
7. 工作台进入封面或图片 AIP 步骤时，默认选择图片模型，并显示推荐提示。
8. 工作台进入最终视频生成时，默认选择视频模型，并显示推荐提示。
9. 如果个人默认存在，优先使用个人默认；否则使用全局默认；再否则使用推荐模型兜底。
10. 如果没有可用模型，生成按钮不可提交，并提示需要配置模型。
11. 生成历史可以看到实际使用的模型 ID、能力类型和默认解析来源。
12. 前端、后端日志、生成快照均不展示明文 API Key。

## 11. 实施阶段

### 阶段一：模型中转底座

完成中转配置表、加密保存、测试连接、模型拉取、模型列表展示。

### 阶段二：默认模型策略

完成全局默认、个人默认、默认解析优先级、工作台模型选择组件接入。

### 阶段三：推荐提示

完成后台推荐标签、推荐原因、风险提示、排序权重和前端展示。

### 阶段四：生成任务闭环

把文字、图片、视频生成执行器统一接入模型解析结果，并保存模型快照。

### 阶段五：智能推荐优化

基于历史成功率、耗时、成本、失败率等数据优化模型推荐排序。
