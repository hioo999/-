# PRD：提词器多文案队列与连续录制

## 1. 背景

现有提词器以单篇口播文案为核心，用户在录制多个口播片段时，需要反复覆盖文案或在外部保存多个稿件，容易出现误覆盖、切换成本高和录制进度不清晰的问题。

本需求将提词器升级为“多篇口播文案队列 + 当前文案切换 + 完成后进入下一篇”的连续录制体验。

## 2. 目标

1. 用户可以在提词器左侧同时添加多篇口播文案。
2. 每篇口播文案可以自定义标题。
3. 用户点击左侧文案卡片即可切换当前录制文案。
4. 每篇文案独立保存状态、滚动位置和完成进度。
5. 当前文案录完后，可以标记完成并切换到下一篇。
6. 已有单篇本地草稿需要自动兼容迁移，不丢历史内容。
7. 提词器左侧不再展示多余操作提示文案，让队列和正文编辑成为主内容。
8. 登录用户可以在提词器中查看自己之前保存过的所有历史口播文案。
9. 粘贴文案时优先保留用户原有分段、分块和标题结构，只对过长句子做轻量提词优化。
10. 全屏提词时文字需要集中在镜头附近的中间阅读区，减少用户左右扫视。
11. 提供眼神模式、镜头安全区校准、录制检查清单、自动风险提醒和练习/正式录制模式。

## 3. 用户流程

1. 用户进入提词器。
2. 系统展示左侧口播队列，默认至少有一篇文案。
3. 用户点击“新增文案”，添加空白口播稿。
4. 用户为每篇文案输入标题和正文。
5. 用户点击某篇文案卡片，右侧提词区域切换到对应内容。
6. 用户点击播放开始录制当前文案。
7. 录制结束后点击“结束”。
8. 系统弹出结束确认，用户可选择“仅标记完成”或“完成并进入下一篇”。
9. 如果选择进入下一篇，系统保存当前文案进度并切换到下一篇待录文案。

## 4. 功能范围

### 4.1 口播队列

左侧新增口播队列模块。

队列项展示：

| 字段 | 说明 |
|---|---|
| 顺序 | 第 1 篇、第 2 篇等 |
| 标题 | 用户自定义标题，默认“口播文案 N” |
| 状态 | 待录、录制中、已完成 |
| 进度 | 当前滚动进度百分比 |
| 时长 | 已完成文案展示录制时长 |

### 4.2 文案管理

支持能力：

| 能力 | 要求 |
|---|---|
| 新增文案 | 新增空白文案并切换为当前文案 |
| 切换文案 | 点击队列卡片切换当前文案 |
| 删除文案 | 支持删除非唯一文案，至少保留一篇 |
| 自定义标题 | 使用现有脚本标题输入框修改当前文案标题 |
| 编辑正文 | 使用现有正文输入框编辑当前文案 |
| 导入文件 | 导入文件后替换当前激活文案 |
| 载入口播文案 | 从工作台传入内容时优先加入队列，避免覆盖已有稿件 |

### 4.3 状态保存

每篇文案需要保存：

| 字段 | 说明 |
|---|---|
| id | 本地唯一 ID |
| title | 文案标题 |
| text | 文案正文 |
| status | todo、recording、done |
| scrollTop | 当前滚动位置 |
| progress | 完成进度百分比 |
| durationSeconds | 完成后的录制时长 |
| updatedAt | 最近更新时间 |

显示设置继续作为全局设置保存，包括速度、字号、行高、主题、镜像、倒计时、阅读宽度、眼神模式、镜头位置和录制模式。

### 4.4 本地兼容

本地缓存升级为 V2 结构：

| 字段 | 说明 |
|---|---|
| version | 固定为 2 |
| activeScriptId | 当前选中的文案 ID |
| scripts | 多篇文案队列 |
| settings | 全局提词器显示设置，包含速度、字号、行高、主题、镜像、倒计时、阅读宽度、眼神模式、镜头位置和录制模式 |
| updatedAt | 最近保存时间 |

如果读取到旧版单篇草稿，需要自动转换为一篇队列文案。

### 4.5 连续录制

结束确认提供两个动作：

| 动作 | 说明 |
|---|---|
| 仅标记完成 | 当前文案标记为已完成，保持当前文案 |
| 完成并进入下一篇 | 当前文案标记为已完成，切换到下一篇未完成文案 |

切换下一篇时不自动播放，避免用户未准备好就开始滚动。

### 4.6 历史口播

登录用户需要能查看自己之前保存过的历史口播文案。

历史口播要求：

| 能力 | 要求 |
|---|---|
| 用户隔离 | 只展示当前登录用户自己的历史口播 |
| 分页展示 | 默认展示最近一批历史文案，支持继续加载更多 |
| 快速打开 | 点击历史文案可加载到当前提词器 |
| 删除历史 | 用户可删除不需要的历史口播记录 |
| 总量提示 | 展示已显示数量和历史总数 |

第一阶段复用现有云端提词草稿接口，不新增后端数据表。

### 4.7 粘贴格式保留与轻量优化

用户复制进来的口播文案通常已经有段落、标题、空行和节奏分块。粘贴时不应全局打散原文结构。

粘贴处理要求：

| 能力 | 要求 |
|---|---|
| 保留分块 | 保留用户原有空行和段落块 |
| 保留标题 | 保留类似“开场：”“第一部分：”等标题行 |
| 保留行结构 | 不把多行内容强制合并成一段 |
| 长句优化 | 仅对超过提词行长的句子做换行 |
| 轻提示 | 粘贴后提示已保留原文结构并优化长句 |

### 4.8 全屏中间阅读区

全屏提词时，文字如果铺满屏幕，用户眼睛会左右扫动，影响面对镜头的观感。全屏模式需要把文字集中到中间阅读区。

阅读区要求：

| 能力 | 要求 |
|---|---|
| 自动居中 | 提词文字居中显示，不铺满全屏宽度 |
| 宽度档位 | 支持窄、标准、宽三档阅读宽度 |
| 参考线 | 全屏下显示两条低透明度竖向安全参考线 |
| 自适应 | 阅读宽度随屏幕尺寸自动 clamp，不使用单一固定宽度 |
| 本地保存 | 阅读宽度档位需要随提词器设置保存和恢复 |

### 4.9 录制辅助

为了减少用户录制失败，提词器需要提供录制前辅助能力。

| 能力 | 要求 |
|---|---|
| 眼神模式 | 支持自然、看镜头、远距离三种预设，联动阅读宽度、字号和行距 |
| 镜头校准 | 支持上方镜头、中间镜头、左上镜头、右上镜头四种安全区位置 |
| 检查清单 | 显示文案、阅读区、字号、倒计时、语音跟读等准备状态 |
| 风险提醒 | 自动提示阅读区偏宽、字号异常、正式录制未开倒计时、文案过长等风险 |
| 录制模式 | 支持练习模式和正式录制模式；练习结束不标记文案完成 |
| 视觉层级 | 全屏下增强当前句和下一句视觉区分，降低口播卡顿 |

## 5. 页面与交互要求

1. 左侧顶部展示口播队列。
2. 当前文案卡片高亮。
3. 已完成文案有明显完成状态。
4. 顶部标题区域展示当前队列位置，例如 `1/3`。
5. 顶部可提供上一篇、下一篇快捷切换。
6. 删除文案需要确认。
7. 至少保留一篇文案，不能删除到空队列。
8. 移除左侧说明文字和默认稿中的快捷键操作提示。

## 6. 非目标

第一阶段不改造后端云端草稿结构，但需要复用现有云端草稿列表作为历史口播入口。

不在第一阶段实现：

1. 云端保存整组多文案队列为一个统一项目。
2. 跨设备同步多文案队列。
3. 拖拽排序。
4. 批量导入多篇文案。
5. 每篇文案独立显示设置。

## 7. 验收标准

1. 用户可以新增至少 3 篇口播文案并分别命名。
2. 点击左侧文案卡片后，标题、正文和提词区域同步切换。
3. 切换文案前会保留当前文案进度。
4. 点击结束后可将当前文案标记为已完成。
5. 点击“完成并进入下一篇”后，系统切换到下一篇未完成文案但不自动播放。
6. 刷新页面后，多篇文案、当前选中项、进度和显示设置可以恢复。
7. 旧版单篇本地草稿可以自动恢复为一篇队列文案。
8. 左侧不再出现“开播中优先用上方播放器...”说明。
9. 默认文案不再包含“操作提示：空格、Esc”等快捷键说明。
10. 登录用户可以看到历史口播总数，并通过“加载更多”查看之前保存过的口播文案。
11. 粘贴已有格式文案后，原来的段落、空行、标题和块结构不被破坏。
12. 全屏提词时，文字区域默认收窄居中，并显示两条安全参考线。
13. 用户可以在窄、标准、宽三档之间切换阅读宽度，刷新后设置仍保留。
14. 用户可以切换自然、看镜头、远距离三种眼神模式。
15. 用户可以选择镜头位置安全区，参考线和文字区域随之调整。
16. 练习模式结束后不把文案标记为已完成；正式录制结束后才进入完成流程。
17. 录制前检查清单和风险提醒能根据当前设置动态变化。
