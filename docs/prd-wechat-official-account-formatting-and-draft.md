# PRD：公众号排版与草稿发布

## 1. 产品判断

本需求应该做，且应作为公众号内容生产闭环的后半段能力：用户完成文章生成或二创后，不应停留在“复制内容”，而应继续完成公众号排版、预览、图片生成、账号校验和发送到微信公众号草稿箱。

第一版不做自动群发发布，只发送到公众号草稿箱。最终发布由用户进入微信公众号后台检查后手动完成，避免误发和权限风险。

## 2. 业务目标

在公众号板块新增“公众号排版与草稿发布”能力，让用户完成内容二创后可以继续完成以下流程：

1. 选择或编辑二创后的文章内容。
2. 一键进入公众号排版器。
3. 选择公众号排版主题。
4. 预览公众号展示效果。
5. 生成封面图或内容配图。
6. 填写或绑定公众号 AppID、AppSecret 等信息。
7. 点击“发送到公众号草稿箱”。
8. 系统自动生成已排版的公众号草稿。
9. 用户去微信公众号后台继续检查、发布。

## 3. 用户流程

1. 用户在系统中生成或二创文章内容。
2. 用户点击“公众号排版”。
3. 系统把文章内容带入排版编辑器。
4. 用户选择排版模板。
5. 用户微调正文、标题、摘要、封面图、配图。
6. 用户点击“预览”查看手机端公众号效果。
7. 用户绑定公众号配置，填写 AppID、AppSecret。
8. 系统校验公众号权限和接口可用性。
9. 用户点击“发送到公众号草稿箱”。
10. 系统创建公众号草稿。
11. 页面提示“已发送到公众号草稿箱”。
12. 用户在微信公众号后台草稿箱中查看。

## 4. 核心功能需求

### 4.1 内容导入

支持从系统已有内容直接进入公众号排版器。

需要字段：

| 字段 | 说明 |
|---|---|
| 文章标题 | 用于编辑器标题和公众号草稿 title |
| 正文内容 | 建议统一为 Markdown，便于转换为公众号 HTML |
| 作者 | 用于公众号草稿 author |
| 摘要 | 用于公众号草稿 digest |
| 标签或选题信息 | 用于内容管理和后续模板推荐 |
| 二创来源内容 | 用于追溯来源与二创依据 |
| 推荐封面图 | 可直接设为封面或作为生成参考 |
| 推荐插图 | 可插入正文或作为配图生成参考 |
| 内容结构 | 小标题、段落、重点句、结尾引导等结构化信息 |

### 4.2 类公众号富文本编辑器

提供类似公众号后台的富文本编辑器，支持用户继续修改二创内容、插入图片和调整公众号样式组件。系统可保留 Markdown 快照用于导出、回退和兼容旧生成链路，但第一阶段主编辑体验以富文本为准。

基础能力：

| 能力 | 要求 |
|---|---|
| 文本格式 | 标题、段落、加粗、斜体、删除线、重点标记 |
| 内容结构 | 引用、无序列表、有序列表、分割线、表格 |
| 公众号组件 | 金句卡、重点段落、引用卡片、关注引导、推荐阅读 |
| 多媒体 | 超链接、图片、图片说明、当前位置插图 |
| 编辑体验 | 撤销/重做、全屏编辑、自动保存、实时预览 |
| 兼容输出 | 保存富文本结构，同时保留 Markdown 快照和公众号 HTML 输出 |

中文公众号内容重点支持：一级标题、二级标题、小标题、金句高亮、重点段落、引用卡片、结尾关注引导、推荐阅读、图片说明。

### 4.3 公众号排版预览

预览要尽量接近微信公众号后台和真实阅读效果。

预览模式：

| 模式 | 要求 |
|---|---|
| 手机预览 | 模拟公众号移动端阅读宽度 |
| 电脑预览 | 模拟桌面端阅读效果 |
| 深色背景预览 | 可选，用于检查图片和卡片边界 |
| 公众号宽度模拟 | 正文宽度、标题区、封面区接近公众号 |
| 封面预览 | 展示封面图、标题、摘要组合效果 |
| 正文预览 | 展示排版后的 HTML 内容 |

### 4.4 排版主题模板

第一版内置主题：默认简洁、科技蓝、中国红、暖阳橙、商务黑金、知识卡片风、个人 IP 风、情绪文案风、成长干货风、女性审美风、极简白底风。

每个主题至少定义：

| 样式项 | 要求 |
|---|---|
| 正文 | 字体、颜色、字号、行距、段落间距 |
| 标题 | 一级标题样式、二级标题样式、标题颜色 |
| 内容组件 | 引用样式、重点文字样式、分割线样式 |
| 媒体 | 图片圆角、图片说明样式 |
| 结构化内容 | 表格样式、代码块样式、结尾引导样式 |

第一版建议内置 6 个高质量模板：知识干货模板、个人 IP 模板、商业分析模板、情绪共鸣模板、科技蓝模板、简洁白底模板。

### 4.5 自定义样式

用户可以在模板基础上微调样式。第一版只做“主题模板 + 少量自定义”，不做复杂自由设计器。

建议支持：主色、辅助色、背景色、正文字号、正文行距、段落间距、标题字号、标题颜色、图片圆角、是否显示装饰线、是否显示标题编号、是否启用卡片式排版。

### 4.6 公众号 HTML 转换

系统需要把 Markdown 转成微信公众号可用 HTML。

关键要求：

| 要求 | 说明 |
|---|---|
| 内联样式 | 所有样式必须内联到 HTML 中，不能依赖外部 CSS |
| 禁止脚本 | 不能依赖 JS，HTML 需要过滤危险标签避免 XSS |
| 图片处理 | 图片必须使用微信公众号素材接口上传后的 URL 或 media_id |
| 兼容结构 | 表格、代码块、引用、标题要转成公众号兼容结构 |
| 特殊内容 | Mermaid、LaTeX 不直接用 HTML，建议转成图片或简化处理 |
| 外链图片 | 先下载，再上传到公众号临时或永久素材 |
| 草稿字段 | 输出内容符合微信公众号草稿接口 content 字段要求 |

### 4.7 图片生成能力

图片生成作为增强功能纳入需求，但第一版可以先做轻量能力。

封面图生成：

| 能力 | 要求 |
|---|---|
| 提示词 | 根据文章标题和内容自动生成封面提示词 |
| 比例 | 支持公众号常用横版比例，如 2.35:1 |
| 风格 | 商务、知识、情绪、国风、科技、人物 IP |
| 使用 | 生成后可设为公众号封面 |
| 上传 | 自动上传到公众号素材，获取 thumb_media_id |

正文配图生成：

| 能力 | 要求 |
|---|---|
| 插图位置 | 自动识别适合配图的位置 |
| 数量 | 每篇文章建议生成 1 到 3 张配图 |
| 类型 | 段落配图、金句图、知识卡片图、一图总结 |
| 插入 | 插图自动插入正文 |
| 上传 | 上传到公众号图片素材接口 |

内容卡片生成：

| 类型 | 适用场景 |
|---|---|
| 金句卡 | 重点观点传播 |
| 总结卡 | 文章结论收束 |
| 方法论卡 | 步骤、模型、框架表达 |
| 对比卡 | 前后对比、方案对比 |
| 人设观点卡 | 个人 IP 观点强化 |
| 结尾引导卡 | 关注、转发、私信引导 |

### 4.8 公众号账号配置

第一版由管理员在后台配置多个公众号账号，普通用户在发送草稿时只能选择已启用且被授权使用的公众号账号。后续阶段再支持用户绑定自己的公众号。

字段：公众号名称、AppID、AppSecret、原始 ID、账号备注、是否默认账号、启用状态、最近测试状态、最近测试时间。

安全要求：

| 要求 | 说明 |
|---|---|
| 密钥存储 | AppSecret 必须加密存储 |
| 前端展示 | 前端不能明文长期展示 AppSecret |
| 权限边界 | 第一版只有管理员可以新增、编辑、停用公众号账号 |
| 用户选择 | 普通用户只能选择管理员授权且启用的公众号账号 |
| 管理能力 | 支持新增、编辑、启用、停用、更新密钥、设置默认账号 |
| 调用边界 | 后端调用微信接口，不允许前端直接调用微信接口 |
| 状态记录 | 记录最近一次授权检测状态 |

需要提供“测试连接”按钮。测试内容包括获取 access_token、检查接口返回错误、检查公众号类型是否支持草稿接口、检查图片上传接口是否可用。

### 4.9 发送到公众号草稿箱

点击发送后，系统调用微信公众号草稿接口。

主要流程：

1. 获取公众号 access_token。
2. 处理正文中的图片。
3. 上传封面图，获得 thumb_media_id。
4. 上传正文图片，替换正文图片地址。
5. 把 Markdown 转成公众号 HTML。
6. 组装草稿文章参数。
7. 调用微信草稿接口。
8. 保存返回的 media_id。
9. 页面提示成功。
10. 用户去公众号后台查看。

草稿接口字段：title、author、digest、content、content_source_url、thumb_media_id、need_open_comment、only_fans_can_comment。

### 4.10 草稿发送结果记录

记录每次发送结果。

记录字段：用户 ID、文章 ID、公众号账号 ID、微信返回的 media_id、发送状态、错误信息、发送时间、草稿标题、封面图、使用的排版主题、是否包含 AI 生成图片、微信接口返回原始错误码。

状态建议：未发送、发送中、发送成功、发送失败、图片上传失败、封面上传失败、token 获取失败、草稿创建失败。

## 5. 页面需求

### 5.1 公众号排版页面

页面结构：左侧类公众号富文本编辑区，中间公众号手机预览区，右侧主题、图片和发布设置区，顶部操作栏。

顶部按钮：返回内容、保存排版、生成封面图、生成配图、预览、复制 HTML、发送到公众号草稿箱。

### 5.2 公众号配置页面

用于管理公众号账号。

功能：新增公众号、编辑公众号、删除公众号、测试连接、设置默认公众号、查看最近发送记录。

第一版不做复杂账号分组和权限，只做启用、停用、默认账号和普通用户可选授权账号。

### 5.3 草稿发送弹窗

点击“发送到公众号草稿箱”后弹窗确认。

字段：选择公众号账号、文章标题、作者、摘要、封面图、原文链接、是否开启评论、是否仅粉丝评论、是否保存当前排版为模板、确认发送。

### 5.4 图片生成弹窗

用于生成封面和正文配图。

字段：图片类型、图片风格、图片比例、生成数量、参考文案、重新生成、插入正文、设为封面。

图片类型包括封面图、正文插图、金句卡、一图总结。

## 7. 数据表需求

### 7.1 公众号账号表

字段：id、owner_user_id、scope、name、app_id、app_secret_encrypted、original_id、is_default、enabled、last_test_status、last_test_message、last_test_at、created_at、updated_at。

说明：第一版 `scope` 以 admin/system 配置为主；后续支持用户绑定时可扩展 user scope。

### 7.2 公众号排版主题表

字段：id、user_id、name、theme_type、config_json、is_system、created_at、updated_at。

### 7.3 公众号草稿发送记录表

字段：id、user_id、article_id、wechat_account_id、title、author、digest、cover_url、wechat_media_id、theme_id、status、error_code、error_message、request_payload、response_payload、created_at、updated_at。

### 7.4 公众号素材表

字段：id、user_id、wechat_account_id、local_url、wechat_url、media_id、material_type、source_type、created_at。

## 8. 微信接口需求

需要对接微信公众号官方接口。

核心接口：获取 access_token、上传图文消息内图片、上传封面素材、新增草稿、获取草稿、删除草稿。

重点注意：

| 风险点 | 处理要求 |
|---|---|
| 账号权限 | AppID 和 AppSecret 只能用于已开通开发能力的公众号，草稿接口需要相应权限 |
| 图片地址 | 图片不能直接使用系统本地地址，需要上传到微信 |
| 封面素材 | 封面图需要 thumb_media_id |
| 正文图片 | 正文图片需要替换成微信可访问的图片 URL |
| token 缓存 | access_token 需要缓存，不能每次重新获取 |
| 频率限制 | 需要做微信接口错误处理和重试边界 |
| 账号类型 | 订阅号、服务号、测试号权限不同，需要测试连接提示 |

## 9. AI 图片生成需求

第一版优先级：封面图生成、金句卡生成、正文插图生成、一图总结生成、自动插入配图。

图片生成输入：文章标题、文章摘要、文章核心观点、用户 IP 风格、账号定位、目标人群、图片风格、图片尺寸。

图片生成输出：图片 URL、图片提示词、图片类型、可插入位置、是否已上传公众号。

## 12. 验收标准

### 12.1 第一版 MVP 验收标准

1. 用户可以从二创内容进入公众号排版页面。
2. 页面可以显示类似公众号后台的富文本编辑器。
3. 页面可以实时预览公众号排版效果。
4. 用户可以选择至少 3 个排版主题。
5. 管理员可以配置多个公众号 AppID、AppSecret 并启用或停用账号。
6. 普通用户可以选择已启用且被授权的公众号账号。
7. 系统可以测试公众号连接。
8. 系统可以自动分析文章结构并建议正文插图位置。
9. 用户可以在正文当前位置一键生成图片并插入。
10. 系统可以把正文图片上传到公众号。
11. 系统可以把封面图上传并获得 thumb_media_id。
12. 用户点击发送后，可以在微信公众号后台草稿箱看到文章。
13. 草稿中的正文已经完成排版。
14. 草稿中的图片可以正常显示。
15. 草稿发送记录按公众号账号保存。
16. 发送失败时，用户能看到明确错误原因。
17. 系统保存每次发送记录。
18. AppSecret 不明文存储。
19. 前端不暴露微信密钥。

### 12.2 增强版验收标准

1. 用户可以生成公众号封面图。
2. 用户可以生成正文配图。
3. 用户可以生成金句卡。
4. 用户可以把生成图片插入正文。
5. 用户可以保存自己的排版模板。
6. 用户可以复用历史公众号账号配置。
7. 用户可以查看历史发送记录。
8. 用户可以复制公众号 HTML。
9. 用户可以导出 Markdown。
10. 用户可以预览手机端效果。

## 13. 关键风险

| 风险 | 应对 |
|---|---|
| 草稿接口权限不稳定 | 绑定后必须提供测试连接，并展示清晰错误原因 |
| AppSecret 泄露 | 加密存储，前端不明文展示，后端代理调用微信接口 |
| 图片上传限制 | 统一格式、大小、频率检查，失败时定位到具体图片 |
| 外链图片不可用 | 发送前统一上传到微信素材并替换正文地址 |
| 公众号 HTML 兼容有限 | 样式全部内联，复杂 Markdown 做降级或转图片 |
| 自动发布风险高 | 第一版只发送草稿箱，不做自动群发 |
| 账号类型差异 | 测试连接时提示订阅号、服务号、测试号权限差异 |

## 14. 参考实现来源

本需求排版和草稿发布链路参考 `https://github.com/maolai7/agent-skills/tree/main/md-to-wechat` 的 `md-to-wechat` 工作流。

可复用的关键设计：

1. 通过 `feishu2weixin` 的 `/api/skill` 接口按账号和主题 ID 渲染 Markdown 为公众号 HTML。
2. 推送前先获取微信公众号 `access_token`。
3. 封面图通过 `material/add_material` 上传为永久图片素材，获取 `thumb_media_id`。
4. 正文外链图片通过 `media/uploadimg` 上传到微信 CDN，并替换正文 HTML 中的图片地址。
5. 最后调用 `draft/add` 创建微信公众号草稿。
6. 遇到 `40164` 时提示用户把服务器公网 IPv4 加入公众号后台 API IP 白名单。

产品化改造边界：

1. 外部脚本只作为实现参考，不直接作为前端调用入口。
2. 公众号 `AppSecret` 从本地 `.env` 改为用户级账号配置，并由后端加密存储。
3. 所有微信接口由后端代理调用，前端不暴露密钥。
4. 每次发送都落库保存状态、错误码、错误信息和微信返回结果。
