# IP全案系统P0需求评审会材料

## 1. 会议目标

本次会议目标是冻结IP全案系统P0范围，确认四条产品线边界、统一底座能力、提词器不动原则，以及Sprint 0启动条件。

会议结论必须回答：

```text
P0做什么
P0不做什么
谁负责什么
哪些技术风险必须先验证
哪些需求进入P1/P2
```

## 2. 参会角色

- 产品经理：说明需求目标、边界、优先级。
- UI/UX设计：确认原型范围和交互风险。
- 前端开发：确认页面、组件、状态、联调风险。
- 后端开发：确认接口、数据模型、公众号和图片模型风险。
- 测试工程师：确认测试范围和验收标准。
- 安全/合规：确认密钥、素材、平台内容风险。

## 3. 项目背景

当前系统需要从偏短视频生产工具，升级为多平台IP全案系统。

重构后的系统结构为：

```text
统一全案底座 + 四条平台产品线
```

四条平台产品线：

```text
公众号
小红书
抖音/视频号
朋友圈/私域
```

统一底座：

```text
IP资产
内容策略
栏目矩阵
选题库
内容母稿
素材库
图片生成
模板库
发布授权
任务状态
```

## 4. P0目标

P0只解决一个核心闭环：

```text
一个IP
一个选题
一份内容母稿
四个平台内容输出
公众号进入草稿箱
其他平台拿到可发布内容包
```

P0成功标准：

- 可以创建IP资产。
- 可以生成策略、栏目、选题、内容母稿。
- 可以生成公众号文章、封面、摘要、排版，并同步草稿箱。
- 可以生成小红书图文发布包。
- 可以生成抖音/视频号脚本和提词器导入稿。
- 可以生成朋友圈正文、评论区和私聊承接话术。
- 提词器模块不受影响。

## 5. P0必须做

| 模块 | P0能力 |
|---|---|
| 全案底座 | IP资产、策略、栏目、选题、母稿 |
| 公众号 | 文章、封面、摘要、排版、草稿同步 |
| 小红书 | 标题、正文、标签、封面、配图、发布包 |
| 短视频 | 抖音/视频号脚本、分镜、字幕、提词稿 |
| 朋友圈 | 正文、评论区第一条、私聊承接话术 |
| 图片生成 | 公众号封面、小红书封面、小红书配图 |
| 授权 | 公众号AppID/AppSecret、图片模型Key |
| 测试 | 主流程、异常、提词器回归 |

## 6. P0明确不做

- 不做公众号直接群发。
- 不做小红书自动发布。
- 不做抖音自动发布。
- 不做视频号自动发布。
- 不做复杂数据看板。
- 不做团队协作和审批流。
- 不做完整CRM。
- 不做多账号矩阵。
- 不改提词器核心功能。

## 7. 四条产品线边界

### 7.1 公众号

P0做：

- 生成文章。
- 生成摘要。
- 生成封面。
- 生成正文配图。
- 自动排版。
- 同步草稿箱。

P0不做：

- 直接群发。
- 多图文合并。
- 复杂公众号数据回收。

### 7.2 小红书

P0做：

- 生成标题。
- 生成正文。
- 生成标签。
- 生成封面和配图。
- 导出发布包。

P0不做：

- 自动发布。
- 账号授权。
- 数据自动回收。

### 7.3 抖音/视频号

P0做：

- 生成脚本。
- 生成分镜。
- 生成字幕重点。
- 生成提词器导入稿。

P0不做：

- 自动发视频。
- 视频剪辑。
- 改造提词器。

### 7.4 朋友圈

P0做：

- 生成朋友圈正文。
- 生成评论区第一条。
- 生成私聊承接话术。
- 生成一周朋友圈计划。

P0不做：

- 自动发朋友圈。
- 客户管理CRM。
- 成交数据归因。

## 8. 技术风险确认

| 风险 | 责任角色 | Sprint 0处理方式 |
|---|---|---|
| 公众号草稿接口权限 | 后端 | 跑真实demo |

| 公众号HTML兼容 | 前端/后端 | 做预览demo和HTML检查 |
| 图片模型质量 | 后端/产品 | 生成公众号封面和小红书样图 |
| 图片文字乱码 | 后端/设计 | 评估模板叠字兜底 |
| AppSecret安全 | 后端/安全 | 加密存储和日志脱敏评审 |
| 提词器误改 | 前端/测试 | 提词器回归测试 |

## 12. 通过标准

本次需求评审通过的标准：

- P0范围无争议。
- P0不做项无争议。
- 公众号、小红书、短视频、朋友圈边界清晰。
- 提词器不动达成共识。
- Sprint 0每个任务有责任角色。
- 关键技术风险有验证方案。

如公众号草稿同步无法确认可行，P0不得进入正式开发，只能继续Sprint 0技术预研。
