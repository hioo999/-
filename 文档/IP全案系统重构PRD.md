## 2. 背景与问题

当前系统已经具备短视频内容生产链路，包括IP资产、栏目规划、选题、钩子、分镜、脚本、视频提示词、质检与复盘等能力。

但现在业务目标已经升级为“IP全案”，服务对象不只是短视频创作者，而是需要同时覆盖公众号、小红书、抖音、视频号、朋友圈/私域等多个内容阵地的用户。

现有系统主要问题如下：

- 全案能力被短视频工作流主导，小红书图文、公众号长文、朋友圈私域内容没有成为一级产品线。
- 内容生成偏单点，缺少从IP定位、内容策略、选题规划、平台适配、发布复盘到下一轮优化的完整闭环。
- 不同平台没有独立工作流，容易把同一份文案简单改写到所有平台，导致平台适配质量不足。
- 公众号不能只生成文章，还需要自动排版、封面生成、配图生成、摘要生成、同步公众号草稿箱。
- 小红书不能只生成文案，还需要接入图片大模型，生成封面、配图、九宫格、图片文字和完整发布包。
- 抖音和视频号虽然同属短视频，但平台表达风格、转化路径、用户信任机制不同，需要分别适配。
- 朋友圈/私域内容目标不是公域爆款，而是信任经营、成交铺垫和私聊承接，需要独立产品线。
- 发布授权、素材管理、图片生成、模板管理、数据复盘缺少统一底座。

## 3. 产品定位

IP全案系统定位为：

```text
一个围绕IP定位、内容策略、图文视频生产、平台适配、发布承接和数据复盘的多平台内容运营系统。
```

系统不再定位为“AI文案生成器”或“短视频提示词工具”，而是定位为：

```text
IP全案系统
= 统一IP策略底座
+ 内容母稿系统
+ 公众号自动排版发布系统
+ 小红书图文生成系统
+ 抖音/视频号短视频生产系统
+ 朋友圈私域内容系统
+ 图片生成中心
+ 发布授权中心
+ 数据复盘中心
```

## 4. 重构原则

### 4.1 前台按产品线拆分

用户前台应看到清晰的平台入口：

```text
公众号
小红书
抖音/视频号
朋友圈/私域
```

每条产品线都应具备独立工作流、独立输出物、独立模板和独立验收标准。

### 4.2 后台统一底座

虽然前台按产品线拆分，但后台必须共用统一底座：

```text
IP资产库
内容策略
栏目矩阵
选题库
内容母稿
素材库
图片生成中心
模板中心
发布授权中心
数据复盘中心
```

避免每个平台各自生成内容，导致IP定位不一致、人设不一致、表达风格不一致、转化路径不一致。

### 4.3 先母稿，再平台适配

单条内容不应直接生成各平台终稿，而应先生成“内容母稿”：

```text
选题
用户痛点
核心观点
论证逻辑
案例素材
金句表达
转化动作
禁用表达
```

然后再根据平台规则生成：

```text
公众号长文
小红书图文
抖音短视频脚本
视频号信任口播
朋友圈私域文案
```

### 4.4 提词器板块不动

本次重构不修改在线提词器既有功能。

全案系统只允许向提词器输出“可导入稿”，包括：

- 抖音口播提词稿
- 视频号口播提词稿
- 直播预热提词稿
- 朋友圈成交口播稿

不改动提词器的全屏、语音跟读、互动暂停、段落跳转、遥控键位等功能。

### 4.5 第一版先做草稿和发布包，不强行自动群发

公众号第一版目标是同步到公众号草稿箱，不直接群发。

小红书、抖音、视频号第一版如果没有稳定官方开放平台能力，则优先做“发布包导出”和“一键复制”，不承诺自动发布。

## 5. 目标用户

### 5.1 个人IP创作者

典型需求：

- 建立专业人设
- 持续输出观点
- 同一选题适配多个平台
- 用公众号沉淀深度内容
- 用小红书承接搜索和种草
- 用抖音/视频号获取曝光和信任
- 用朋友圈促进咨询和成交

### 5.2 企业品牌运营者

典型需求：

- 产品种草
- 品牌内容矩阵
- 公众号品牌文章
- 小红书种草笔记
- 短视频推广脚本
- 私域转化内容
- 多平台内容日历

### 5.3 短视频团队/代运营团队

典型需求：

- 多客户IP建档
- 多平台内容批量生产
- 内容模板复用
- 生成封面、脚本、图文、公众号排版
- 管理选题状态和发布状态
- 基于数据复盘优化选题

### 5.4 老板IP/专家IP

典型需求：

- 建立信任
- 输出行业观点
- 沉淀案例文章
- 生成视频号口播
- 发布朋友圈成交内容
- 承接私域咨询

## 6. 产品目标

### 6.1 业务目标

- 将系统从短视频生产工具升级为多平台IP全案工作台。
- 提升用户从策略到内容生产再到发布复盘的完整闭环效率。
- 让公众号、小红书、短视频、朋友圈成为可独立交付的产品线。
- 支持用户围绕同一IP和同一选题快速生成多平台内容包。

### 6.2 用户目标

- 用户能快速完成IP建档和定位。
- 用户能生成长期内容栏目和选题库。
- 用户能针对同一选题生成公众号、小红书、短视频、朋友圈版本。
- 用户能为公众号自动生成封面、配图、摘要、排版，并同步到公众号草稿箱。
- 用户能为小红书自动生成文案、封面、配图、九宫格和完整发布包。
- 用户能为抖音/视频号生成脚本、分镜、封面、字幕、提词器导入稿。
- 用户能为朋友圈生成成交型内容、九宫格图、海报和私聊承接话术。

### 6.3 产品指标

建议第一阶段关注：

| 指标 | 定义 |
|---|---|
| IP建档完成率 | 创建IP后完成核心资料填写的比例 |
| 内容母稿生成率 | 用户创建选题后成功生成母稿的比例 |
| 多平台适配率 | 同一母稿生成2个及以上平台内容的比例 |
| 公众号草稿同步成功率 | 公众号内容成功进入草稿箱的比例 |
| 小红书发布包导出率 | 小红书图文包被导出或复制的比例 |
| 短视频提词稿导出率 | 短视频脚本导出为提词器稿的比例 |
| 复盘填写率 | 发布后填写数据的内容占比 |

## 9. 核心业务流程

### 9.1 新IP完整全案流程

```text
创建IP档案
↓
填写基础资料、目标用户、商业目标、平台选择
↓
生成IP定位与内容策略
↓
生成栏目矩阵
↓
生成选题库和内容日历
↓
选择选题进入内容工作台
↓
生成内容母稿
↓
选择平台适配
↓
生成公众号/小红书/短视频/朋友圈内容
↓
导出发布包或同步草稿
↓
发布后填写数据
↓
系统生成复盘和下一轮选题建议
```

### 9.2 已有IP快速生产流程

```text
选择已有IP
↓
选择已有栏目或新建选题
↓
生成内容母稿
↓
选择平台产品线
↓
生成平台内容
↓
导出/同步草稿
```

### 9.3 单平台快速入口流程

```text
进入公众号/小红书/短视频/朋友圈
↓
选择IP或临时输入资料
↓
输入主题或素材
↓
系统自动补全策略上下文
↓
生成对应平台内容
↓
编辑、预览、导出或同步
```

### 9.4 多平台一键分发流程

```text
选择一个选题
↓
生成内容母稿
↓
勾选目标平台：公众号、小红书、抖音、视频号、朋友圈
↓
系统生成各平台版本
↓
用户分别进入平台工作台微调
↓
导出发布包或同步草稿
```

## 16. 权限与安全需求

### 16.1 密钥安全

- AppSecret、API Key必须加密存储。
- 前端不得暴露完整密钥。
- 支持密钥更新和删除。
- 授权测试失败时不泄露敏感信息。

### 16.2 素材安全

- 用户上传素材应与所属IP绑定。
- 删除IP时需要提示是否保留素材。
- 素材引用应记录来源和授权状态。

### 16.3 内容合规

系统应在生成结果中提示潜在风险：

- 广告法极限词
- 医疗、金融、教育等敏感行业风险
- 虚假承诺
- 平台违规引流
- 侵犯肖像权、商标权、版权风险

## 17. 异常场景

### 17.1 公众号异常

| 场景 | 系统处理 |
|---|---|
| AppID/AppSecret错误 | 提示授权失败，检查配置 |
| access_token过期 | 自动刷新，刷新失败则提示重新授权 |
| IP白名单未配置 | 提示到公众号后台配置服务器IP |
| 封面上传失败 | 提示图片格式、大小或权限问题 |
| HTML不兼容 | 提示不兼容元素并建议重新排版 |
| 草稿同步失败 | 展示接口错误码和处理建议 |

### 17.2 图片生成异常

| 场景 | 系统处理 |
|---|---|
| 模型接口失败 | 支持重试或切换模型 |
| 图片文字乱码 | 提示使用模板叠字替代模型生成文字 |
| 主体不一致 | 支持引用原图重新生成并强化一致性提示 |
| 内容违规 | 提示修改提示词或更换表达 |
| 生成超时 | 展示任务状态并允许后台生成 |

### 17.3 内容生成异常

| 场景 | 系统处理 |
|---|---|
| IP资料不足 | 提示补充关键字段 |
| 母稿缺少观点 | 提示补充核心观点或案例 |
| 平台风格不匹配 | 支持重新选择平台风格 |
| 输出过短/过长 | 支持按字数重新生成 |

## 22. 待确认问题

以下问题需要在进入设计和开发前确认：

- 公众号是否只支持服务号/订阅号草稿同步，还是都要支持。
- 当前是否已经有可用服务器IP用于配置公众号白名单。
- ChatGPT Image / image2 的具体API供应方式、额度和计费策略。
- 图片存储使用本地、对象存储还是第三方图床。
- 小红书是否已有官方开放平台发布权限。
- 抖音/视频号是否已有官方开放平台发布权限。
- 是否需要多用户、多团队、多客户空间。
- 第一版是否需要内容审核流。
- 是否需要内置行业模板，例如教育、知识付费、本地生活、品牌产品、门店探店。

## 23. 小P结论

本次全案重构应明确采用：

```text
统一全案底座 + 平台产品线拆分
```

前台按平台拆成：

```text
公众号
小红书
抖音/视频号
朋友圈
```

后台统一复用：

```text
IP资产
内容策略
栏目矩阵
选题库
内容母稿
素材库
图片生成
模板库
发布授权
数据复盘
```

第一版最关键的交付不是“多生成几段文案”，而是打通四个核心生产闭环：

```text
公众号：文章 + 图片 + 封面 + 摘要 + 排版 + 草稿同步
小红书：文案 + 封面 + 配图 + 九宫格 + 发布包
短视频：钩子 + 脚本 + 分镜 + 字幕 + 封面 + 提词器稿
朋友圈：信任文案 + 九宫格/海报 + 评论区 + 私聊承接
```

提词器保持独立，只作为短视频/口播内容的承接环节，不进入本次重构范围。
