我先把你的框架收敛成“平台级重构方案”，重点不是马上写代码，而是先确定产品边界、模块关系、通用底座和第一阶段落地顺序。明白。你现在不是要在原系统上零散加功能，而是要把 **IP 打造全案系统** 重构成一个“多平台内容生产 + AI 二创 + 图片/视频生成 + 发布闭环”的内容工厂。

我的判断是：**这个方向是对的，但不能按 6 个孤立模块各做一套流程，否则会重复开发、维护困难、提示词混乱、数据无法复用。应该先抽象出统一底座，再按平台/内容类型做业务版块。**

**一、总体产品定位**

新的系统可以定义为：

**IP 全案内容生产工作台**

帮助用户从一个主题、链接、原始文本、图片素材、人物/产品/宠物素材出发，生成适配不同平台的内容，并继续完成排版、配图、封面、提词、视频生成和发布草稿。

核心闭环是：

`素材/主题输入 → 内容提取 → 选择平台/场景 → 选择后台提示词模板 → AI 生成内容 → 编辑打磨 → 配图/封面/分镜/提词 → 发布或出片`

所以重构后的系统不应该叫单一的“IP 工作台”或“口播生成器”，而应该拆成：

1. **公众号内容生产**
2. **小红书内容生产**
3. **视频号/抖音口播内容生产**
4. **短大片视频生成**
5. **剧本短视频生成**
6. **提词器工具**
7. **后台提示词与账号配置中心**
8. **素材库、角色库、作品库**

**二、推荐系统架构**

我建议按“通用底座 + 业务版块 + 后台运营”三层重构。

**1. 通用底座**

这部分所有版块共用，不能每个模块重复做。

| 底座 | 作用 |
|---|---|
| 素材输入中心 | 支持主题、链接、粘贴文本、文件、图片、视频上传 |
| 内容提取服务 | 链接解析、正文提取、图片识别、视频摘要、文件解析 |
| 提示词模板中心 | 后台配置不同平台、场景、步骤的提示词 |
| AI 生成任务中心 | 所有文案、图片、视频生成都走统一任务模型 |
| 内容编辑器 | 支持 Markdown、富文本、结构化字段编辑 |
| 图片生成服务 | 支持 ChatImage2、其他图片模型、封面图、正文插图、分镜图 |
| 视频生成服务 | 接入现有视频引擎，支持分步骤任务状态 |
| 素材库 | 保存原始素材、生成图、封面、分镜、视频 |
| 作品库 | 保存公众号文章、小红书笔记、口播稿、视频项目、剧本项目 |
| 发布配置中心 | 保存公众号 AppID/AppSecret、小红书/抖音可先做导出，后续再接 API |
| 用户与权限 | 普通用户使用模板，管理员维护模板、账号、模型配置 |

**2. 业务版块**

每个版块不是独立系统，而是基于统一底座编排不同流程。

| 版块 | 核心产物 | 后续动作 |
|---|---|---|
| 公众号 | 公众号文章、摘要、封面、正文图片 | 公众号排版、发送草稿箱 |
| 小红书 | 标题、正文、标签、封面、多图笔记 | 图片生成、导出发布素材 |
| 视频号/抖音 | 口播文案、标题、描述、标签、录屏脚本、封面 | 进入提词器、生成封面、出片 |
| 短大片 | 主体图、三视图/四视图、九宫格、分镜图、视频 | 分步骤生成视频 |
| 剧本短视频 | 角色、剧本、分镜表、分镜图、视频 | 多集剧本、角色复用 |
| 提词器 | 可录制口播稿 | 全屏提词、速度调节、段落跳转 |

**3. 后台运营中心**

这个系统要长期可运营，后台非常关键。

| 后台模块 | 说明 |
|---|---|
| 提示词分类管理 | 平台、场景、步骤、行业、风格、模型类型 |
| 提示词模板管理 | 新增、编辑、启用、停用、版本、默认模板 |
| AI 模型配置 | 文本模型、图片模型、视频模型、默认参数 |
| 公众号账号配置 | AppID、AppSecret、默认封面、主题 ID |
| 图片生成配置 | ChatImage2、其他模型、尺寸、风格、数量 |
| 视频生成配置 | 秒数、比例、模型、分镜参数 |
| 角色库管理 | 人物、宠物、产品角色资产、特征、参考图 |
| 生成记录 | 每次生成使用了什么素材、模板、模型和参数 |
| 发布记录 | 公众号草稿发送记录、错误码、media_id |
| 数据看板 | 生成成功率、编辑率、发布率、出片成功率 |

**三、六大版块产品方案**

**1. 公众号版块**

公众号应该是第一优先级，因为它闭环最完整：输入、二创、排版、配图、发送草稿箱。

主流程：

1. 用户进入公众号内容生产。
2. 选择输入方式：链接、粘贴原文、主题。
3. 系统提取或接收原始内容。
4. 用户选择后台配置的提示词分类和模板。
5. 系统生成公众号二创内容。
6. 用户进入公众号排版版块。
7. 在排版编辑器里编辑标题、作者、摘要、封面、正文。
8. 用户可以自动生成封面图。
9. 用户可以在正文不同位置一键生成插图。
10. 用户可以生成简介部分、导语、结尾引导。
11. 用户点击预览，系统生成公众号 HTML。
12. 用户点击发送。
13. 后端读取后台保存的公众号 AppID 和 AppSecret。
14. 系统获取 access_token，上传封面图，上传正文图片，创建草稿。
15. 用户到公众号后台检查草稿并手动发布。

公众号版块核心页面：

| 页面 | 功能 |
|---|---|
| 公众号内容生成页 | 链接/文本/主题输入，选择提示词，生成二创内容 |
| 公众号排版页 | Markdown/富文本编辑、预览、主题样式、图片插入 |
| 公众号账号配置页 | AppID、AppSecret、默认封面、测试连接 |
| 公众号发送记录页 | 成功/失败记录、media_id、错误信息 |

MVP 必须做：

| 优先级 | 功能 |
|---|---|
| P0 | 链接/文本/主题生成公众号文章 |
| P0 | 后台提示词选择 |
| P0 | 公众号排版编辑 |
| P0 | 自动生成封面 |
| P0 | 正文中插入 AI 图片 |
| P0 | 发送到公众号草稿箱 |
| P1 | 多排版主题 |
| P1 | 图片位置智能推荐 |
| P1 | 发送记录与失败重试 |

**4. 短大片视频版块**

这个版块是视觉视频生成，适合产品、宠物、人物 IP、空间、生活方式等。

你给的流程是对的，但我建议产品上把它做成 **分步骤工作流**，不要一次性全自动黑盒生成。

主流程：

1. 用户上传产品、宠物或人物图片。
2. 选择项目类型：产品大片、宠物大片、人物 IP、空间展示等。
3. 系统根据第一步提示词清除背景，生成主体图。
4. 系统根据第二步提示词生成三视图或四视图。
5. 系统根据第三步提示词生成九宫格风格探索图。
6. 系统根据第四步提示词生成分镜图。
7. 系统生成分镜词、镜头运动、时长、比例、风格。
8. 用户选择要使用的主体图、视图、九宫格、分镜图。
9. 上传所需素材到视频引擎。
10. 系统生成视频。
11. 用户预览、下载、重试或继续优化。

短大片的关键是每一步都要有独立提示词：

| 步骤 | 提示词类型 |
|---|---|
| 主体清理 | 背景清除、主体保真、透明底或纯色底 |
| 三视图/四视图 | 角色/产品一致性、多角度视图 |
| 九宫格 | 风格探索、场景变化、镜头氛围 |
| 分镜图 | 镜头构图、动作、场景、光影 |
| 视频生成 | 时长、比例、运镜、主体一致性 |

MVP 必须做：

| 优先级 | 功能 |
|---|---|
| P0 | 上传图片 |
| P0 | 主体图生成 |
| P0 | 三视图/四视图生成 |
| P0 | 九宫格生成 |
| P0 | 分镜图生成 |
| P0 | 分镜词生成 |
| P0 | 提交视频生成任务 |
| P1 | 每一步模板可选 |
| P1 | 默认模板自动推荐 |
| P1 | 中间结果可保存到素材库 |

**5. 剧本短视频版块**

这个版块和“短大片”不同，核心不是单个主体美学视频，而是 **角色资产 + 剧情脚本 + 多集内容 + 分镜生成 + 视频生成**。

主流程：

1. 用户上传多个人物全身照。
2. 系统为每个人生成四视图、八视图或角色设定图。
3. 用户补充人物名称、年龄、性格、人设、关系。
4. 系统保存到人物角色库。
5. 用户输入剧本主题。
6. 用户选择角色。
7. 用户选择剧本类型：反转剧、情感剧、知识剧情、带货剧情、职场剧情等。
8. 系统生成单集或多集剧本。
9. 用户确认每集标题、剧情、台词、转折点。
10. 系统生成分镜表。
11. 系统生成分镜图。
12. 用户选择秒数、比例、风格和视频模型。
13. 系统生成视频。

角色库应该保存：

| 字段 | 说明 |
|---|---|
| 角色名称 | 用户自定义 |
| 角色图片 | 原始图、四视图、八视图 |
| 性格 | 外向、毒舌、温柔、专家型等 |
| 人设 | 老板、宝妈、医生、老师、创业者等 |
| 语言风格 | 犀利、幽默、专业、温柔等 |
| 关系设定 | 与其他角色的关系 |
| 可复用状态 | 后续剧本可直接调用 |

MVP 必须做：

| 优先级 | 功能 |
|---|---|
| P0 | 上传人物全身照 |
| P0 | 生成四视图/角色设定图 |
| P0 | 保存角色 |
| P0 | 输入主题并选择角色 |
| P0 | 生成短剧剧本 |
| P0 | 生成分镜表 |
| P1 | 生成分镜图 |
| P1 | 多集剧本 |
| P1 | 提交视频生成 |

**6. 提词器小工具**

提词器应该独立成工具，但入口可以来自口播文案、视频号/抖音、公众号转口播、小红书转口播。

提词器不是内容生成模块，它负责录制执行。

主流程：

1. 用户从口播文案点击“发送到提词器”。
2. 提词器自动载入稿件。
3. 用户设置字号、速度、行距、背景、镜像、段落模式。
4. 用户开始提词。
5. 支持暂停、继续、上一段、下一段。
6. 支持全屏模式。
7. 后续增强语音跟读、互动暂停、遥控键位。

MVP 必须做：

| 优先级 | 功能 |
|---|---|
| P0 | 接收口播文案 |
| P0 | 全屏提词 |
| P0 | 字号、速度、行距调整 |

**四、后台提示词体系设计**

这次重构最核心的是：**所有提示词都必须后台配置，前端只选择模板，不暴露系统提示词全文。**

提示词模板建议按以下维度设计：

| 字段 | 说明 |
|---|---|
| template_id | 模板 ID |
| template_key | 模板唯一 Key |
| name | 模板名称 |
| platform | 公众号、小红书、抖音、视频号、短大片、剧本 |
| scene | 二创、口播、标题、封面、图片、分镜、视频 |
| step | 当前属于哪个步骤 |
| category | 分类，如知识、种草、剧情、品牌、直播 |
| model_type | text、image、video |
| default_model | 默认模型 |
| system_prompt | 后台系统提示词 |
| user_prompt_template | 用户提示词模板 |
| output_schema | 输出结构 |
| parameters | 可配置参数 |
| version | 版本号 |
| status | 草稿、启用、停用 |
| is_default | 是否默认 |
| sort_order | 排序 |
| created_by | 创建人 |
| updated_at | 更新时间 |

提示词示例分类：

| 平台 | 分类 |
|---|---|
| 公众号 | 深度观点、案例拆解、品牌宣传、知识科普、产品种草 |
