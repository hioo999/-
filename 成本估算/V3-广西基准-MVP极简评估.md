# 🏛️ 律师 AI 知识库演示型 MVP 成本评估 V3（广西基准）

> **基准：** 广西 2026 年 IT 薪资 ｜ **AI 写代码（Cursor/Copilot）** ｜ 只算演示型/内部试用型 MVP

> [!IMPORTANT]
> 本评估适用于“演示型 MVP”或“小范围内部试用版”，不适用于正式商业化交付预算。
> 如果目标是给律所真实稳定使用，需额外考虑权限安全、文档解析、RAG 准确率、法律语料整理、审计日志、运维监控和上线后迭代成本。

---

## 一、核心前提

| 条件 | 说明 |
|------|------|
| AI 写代码比例 | **代码文本生成可达 ~80%**（Cursor + Copilot 生成，人工审查调整） |
| 人的角色 | 架构设计、需求拆解、AI 提示、审查调试、集成联调 |
| 工时缩减系数 | 演示型 MVP 可压到传统开发的 **1/3 左右**；真实试用型建议按 **40-60% 缩减** 估算 |
| 地点 | 广西（南宁/柳州/桂林） |

### MVP 边界

| 类型 | 包含 | 不包含 |
|------|------|--------|
| 演示型 MVP | 登录、文件上传/同步、基础文档解析、基础 RAG 问答、简单后台、单租户 | 多租户、复杂权限、OCR、审计合规、高可用、商业化运维 |
| 内部试用型 MVP | 角色权限、文件分类、解析状态、引用来源、基础日志、小范围上线 | 大规模并发、复杂案件流转、深度法律工作流、完整 SaaS 能力 |

## 三、MVP 功能 & AI 辅助工时

### 演示型 MVP：AI 写代码后的基准工时

| 模块 | 传统人天 | AI 辅助后人天 | 说明 |
|------|---------|-------------|------|
| 用户系统（登录/权限） | 22 | **5** | 成熟模板，AI 秒生成 |
| 服务器连接配置 | 29 | **8** | 表单 + 连接测试，逻辑不复杂 |
| 远程文件管理 | 31 | **10** | 仅按基础 SFTP/API 文件列表、上传、下载估算 |
| AI 知识库引擎（RAG） | 53 | **18** | 仅限基础 RAG Demo，需要人工调优 Prompt 和检索策略 |
| 智能问答界面 | 44 | **10** | 前端 Chat UI，AI 生成很快 |
| 后台管理 Dashboard | 32 | **8** | Admin 面板模板化程度高 |
| 基础架构 & 部署 | 14 | **5** | Docker Compose 一把梭 |
| 联调测试 | 18 | **10** | 这个 AI 帮不了太多，靠人 |
| **合计** | **243** | **74** | **缩减 70%** |

> [!TIP]
> 74 人天 ≈ **1 个人干 3.5 个月**，或 **2 个人干 2 个月**

### 内部试用型 MVP：建议修正工时

| 模块 | 建议人天 | 增加原因 |
|------|---------|----------|
| 远程文件管理 | **14-20** | 需要文件分类、解析状态、重复文件识别、删除后的索引清理 |
| AI 知识库引擎（RAG） | **25-35** | 法律文档切片、混合检索、引用来源、幻觉控制、真实样本文档调优 |
| 联调测试 | **15-25** | 需要验证回答准确性、权限隔离、引用溯源、异常文档处理 |
| 基础安全与日志 | **5-10** | 至少需要操作日志、API Key 管理、备份和错误追踪 |
| **总计** | **90-120 人天** | 更接近律所内部小范围试用的真实工作量 |

## 六、不同场景的费用区间

| 场景 | 费用 | 周期 | 前提 |
|------|------|------|------|
| **自己就是开发者 + AI** | **3-5万** | 2-3 月 | 只做演示型 MVP，自己懂全栈、RAG 和部署 |

```

          ─────────────────────────
          演示型：约 2.5-3 个月
          内部试用型：建议按 3-4 个月规划
```

## 八、省钱要点

| 策略 | 省多少 | 怎么做 |
|------|--------|--------|
| 用 DeepSeek 替代 GPT-4 | API 成本降 **90%** | 国产模型效果够用且便宜 |
| Cursor 写 80% 代码 | 演示型人力可省 **50-70%** | 关键是核心开发要会拆需求、审代码、调 RAG |
| UI 用现成组件库 | 设计费省 **50%** | Ant Design / Arco Design，改改就能用 |
| Docker Compose 部署 | 不需要 DevOps | 比 K8s 简单 100 倍 |
| 广西招人 | 人力成本降 **40-50%** | 相比广州 |

## 九、隐藏成本与风险

| 风险项 | 影响 | 建议 |
|--------|------|------|
| 法律语料整理 | 律师文件往往混杂、重复、过期或涉密，不整理会影响问答质量 | 安排律师/助理参与资料筛选、脱敏、分类和验收 |
| 文档解析 | PDF、Word、扫描件、表格、图片证据格式差异大 | 演示型只支持文本型 PDF/Word；OCR 另算 |
| RAG 准确率 | 能跑通不等于律师敢用，错误引用和幻觉会直接影响信任 | 必须做引用来源、拒答机制和样本文档测试集 |
| 权限安全 | 律师资料涉及客户隐私、商业秘密和案件策略 | 内部试用型至少要做角色权限、文件权限、操作日志 |
| 上线运维 | 100 元/月服务器只适合开发，不代表可用上线环境 | 试用期建议按 300-1000 元/月估算运行资源 |
| AI API 成本 | 开发期成本低，但上线后受文档量和问答频次影响 | 单独记录 token、Embedding、重排和 OCR 费用 |

## 十、验收口径

### 演示型 MVP 验收

| 项目 | 验收标准 |
|------|----------|
| 用户登录 | 可登录、退出、区分基础角色 |
| 文件入库 | 支持少量文本型 PDF/Word 上传或同步 |
| 文档解析 | 可展示解析状态，失败有提示 |
| 知识库问答 | 可基于指定文档回答，并展示引用来源 |
| 后台管理 | 可管理用户、文件、知识库任务和基础配置 |
| 部署 | 可在一台云服务器上通过 Docker Compose 运行 |

### 内部试用型 MVP 增补验收

| 项目 | 验收标准 |
|------|----------|
| 权限隔离 | 用户只能检索和问答自己有权限的文件 |
| 引用溯源 | 每个答案能追溯到原文片段或文件 |
| 失败处理 | 解析失败、检索不到、模型超时有明确提示 |
| 安全日志 | 记录登录、上传、删除、问答等关键操作 |
| 真实样本测试 | 使用 30-100 份真实或脱敏法律文档做问答验证 |
| 试运行 | 至少 1-2 周小范围试用并修复高优先级问题 |

## 十一、结论

> ### 📊 一句话
> 
> **广西团队 + AI 写代码，演示型 MVP 做下来 8-10 万，2.5-3 个月交付是合理的；如果要给律所内部真实试用，建议按 10-15 万、3-4 个月规划。**
> 
> 如果核心开发者自己就在团队里，演示型 MVP 的纯增量支出 **5-6 万** 有机会成立。

| 目标 | 建议预算 | 建议周期 | 判断 |
|------|----------|----------|------|
| 演示型 MVP | **8-10万** | **2.5-3个月** | 原评估基本合理 |
| 内部试用型 MVP | **10-15万** | **3-4个月** | 更适合作为正式立项预算 |
| 商业化交付版本 | **18-35万+** | **4-6个月** | 原评估明显低估 |

*核心风险：取决于那个“懂 AI + 全栈 + RAG + 法律业务场景”的核心开发者能不能找到——这个人的水平决定了项目成败。AI 能提高写代码速度，但不能替代产品取舍、法律语料治理、检索效果调优和上线质量控制。*
